# ZMark 第三期《今晚要发版》制作规格

修订：r2，2026-11-24。状态：已制作，成片待用户试听验收。r1 的分镜已获确认；r2 按实测旁白时长和制作结果修订，变化见文末。

已定：故事线 A；简体中文人声旁白，用 HyperFrames 内置 Kokoro 本地 TTS `zf_xiaobei` 生成；时长 60–75 秒，先做中文版；3D 只用于生成内容。

```text

OUTPUT:  HyperFrames 0.9.74，1920×1080，60 fps，H.264 + 48 kHz 立体声 AAC
TIME:    目标 68 s × 60 = 4080 帧；以实际旁白时长为准，允许 62–72 s
LOOK:    两个场景：夜色书桌（#1C1D21，2% 颗粒）和 ZMark 浅色工作台（取 zmark-v2/palettes.css）
         强调色琥珀 #F59E0B，每个镜头只用在一个焦点上：光标、当前段落、选中标题或片尾按钮

         ZMark 图标 PNG 作为薄板贴图；ZMark 窗口、工具栏、Drawer、大纲和预览全部来自真实界面
MOTION:  入场 expo.out 0.5 s；界面内移动 power2.inOut 0.6–0.95 s；离场 power2.in 0.35 s；
         镜头推拉 0.45–0.6 s，带运动模糊；3D 只用平移、俯冲和展开，不环绕旋转；元素错开 6–10 帧
```

时间是计划值。旁白生成后用 `hyperframes transcribe` 取词级时间戳，再把每个镜头起点对到锚词。屏幕文字只放快捷键、文件名和短标签。

## 素材与真实性

- 截图或录屏：以 0.2.12 本机安装版为准，录制新建草稿、分屏同步滚动、Mermaid 渲染、灯箱、大纲跳转、首次保存和自动保存。录制使用专用演示 Workspace Root，不出现个人文件。
- 演示文稿 `release.md` 写入工程 `assets/`，Mermaid 源同时由 `zmark_core::mermaid::render_to_svg_themed` 导出 SVG，保证预览与 3D 节点文字一致。
- 夜色书桌与时钟是故事场景，不冒充产品界面；所有快捷键以 README 快捷键表为准。
- 音乐：沿用 zmark-v2 的 CC BY 曲目会与上期雷同，计划从免版税曲库另选一首并写入 `CREDITS.md`；若 HeyGen 曲库不可用，就去 incompetech 选择同类 CC BY 曲目。

## 制作步骤

1. 复制 zmark-v2 的字体、图标和调色板，新建 `promo/zmark-v3/` HyperFrames 工程，每个镜头一个 sub-composition。
2. 运行 `hyperframes tts` 生成旁白，并运行 `transcribe` 取得时间戳，按锚词确定根时间轴的总时长。
3. 用录屏素材重建界面状态，再接入 3D 开场、Mermaid 俯冲和片尾这三段 Three.js 场景。
4. 运行 `hyperframes check`、`snapshot --review`，然后写 `REVIEW.md`；在预览中给你验收，通过后才渲染交付。

## QA 清单

- 第 0 帧不是黑屏，能看到 `22:00` 与 3D `#`。
- 第 10.5、35.0、44.0、62.5 秒接缝前后各抽 3 帧，3D 与真实界面衔接时文字不跳动、不被遮挡。
- 每个快捷键提示与当帧界面状态一致；`⌘S` 镜头中草稿取消/保存语义与 0.2.12 行为一致。
- 3D 最重的一帧（俯冲穿过节点）单帧绘制时间低于 250 ms。
- 旁白和画面文字没有逐字重复；字幕区在 80% 标题安全框内。
- 成片 `hyperframes audio --json`：旁白存在，−14 LUFS 左右，真峰值 ≤ −1 dBTP。报告注明“测量所得，未经人耳试听”。

## 自查记录（r1，非独立审查）

按项目约定由当前代理自查，结论由用户确认。

- 假设：Kokoro 中文发音能读对 “ZMark”“Markdown”“Mermaid”。风险：英文词可能读错。处理：先生成 10 秒样音，必要时改写为音译或换英文声线念产品名。
- 假设：片中只展示 0.2.12 已有功能。已核对 README 快捷键表、草稿首次保存行为和 Mermaid 本机渲染。
- 风险：3D 三段会拉长渲染时间。上期 35 秒 1440p 的渲染耗时没有记录，本期 1080p 68 秒的耗时只能在第一次草渲后估计。
- 未决：英文版、竖版切片和配乐曲目另行确认，不阻塞中文版开工。

## r2 制作修订

- 时长按 11 句旁白实测（58.3 s）定为 72 s，4320 帧。旁白起点：0.6、6.7、13.5、16.9、23.4、30.6、38.5、44.5、51.2、58.9、63.9 s。
- 场景：night 0–14.4，draft 14.4–23.0，split 23.0–38.3，dive 38.3–44.4，outline 44.4–58.5，finale 58.5–72.0。3D 俯冲在 40.5–43.1 s，上升音效接重击落在 43.1 s 回到平面灯箱 300% 的那一帧。
- 配乐选《Chill Wave》（100 BPM，CC BY 4.0），138.9 s 起截取，使 153.6 s 的强拍落在 14.5 s 的“打开 ZMark”。旁白下用侧链压低音乐。
- 演示文档改为 0.2.12 与 0.2.13 的真实发布要点；流程图改为 4 个节点（写草稿、校对、打包构建、发布），6 个节点在预览栏里太小。
- 工作画布 1280×720，渲染 2560×1440，另缩出 1080p。渲染器只支持整数倍缩放，不能直接从 1280 宽出 1080p。
- 产品界面按源码重建（本机没有录屏权限）。片尾地址改为 `github.com/2716190547/zmark/releases`。

## r3 优化方案（2026-11-24，用户确认）

用户对 r2 的反馈：开头不抓眼球；旁白口音怪；结尾 3D 没有冲击力；配乐平淡；3D 模型颜色脏。

| 问题 | 原因 | r3 决定 |
| --- | --- | --- |
| 开头 | 第 0 帧只有一个小 `#` 漂在暗场，前 5 秒没有动作 | 符号风暴：第 0 帧就有几十个 3D Markdown 符号（`#` `*` `>` `-` `[ ]` 反引号）迎面扑来，镜头穿过它们；1.81 s 一个大 `#` 砸进空白文稿 |
| 旁白 | Kokoro 中文声线把英文词和声调读错，转写只对上不到一半 | 去掉旁白，改由每镜一句短标题（≤ 8 字）卡在小节线上逐字落下，快捷键提示放在标题同一行右侧 |
| 配乐 | 《Chill Wave》整首能量几乎恒定 | 换《EDM Detection Mode》（128 BPM，CC BY 4.0）：用 121–135 s 的 build 垫开场，135.0 s 的 drop 落在 14.0 s 的 ZMark 亮相；51.5 s 在小节线上接到全曲尾段，最后一记重拍落在 53.375 s 的图标落定 |
| 结尾 3D | 只是图标放大翻正，镜头和光都不动 | 碎片汇聚：预览页碎成全片出现过的 3D 元素（符号、流程图节点、版本号和平台名卡片）先炸开，再旋转汇聚成图标；镜头绕 35° 落到正面，环境反射扫过渐变 Z |
| 3D 颜色 | ACES 色调映射压灰、只有定向光、无环境反射、琥珀偏褐 | 光滑烤漆：品牌红橙渐变 `#C24127` → `#F49D0B` 加白瓷两种材质，清漆反光，RoomEnvironment 影棚环境光，中性色调映射；开场底色改为干净的 `#0F1117`、去掉颗粒；片尾改为暖白底 |

时长缩到 58.8 s（3528 帧），镜头顺序不变，切点卡 128 BPM 的小节线（1.875 s，以 14.0 s 为零点）：

| 时间（s） | 场景 | 标题 |
| --- | --- | --- |
| 0–14.0 | night：符号风暴 → 1.81 s 砸进文稿 → 资料散乱 → 原文淹没 | 发布说明还是空的 / 资料散了一桌 / 越写越乱 |
| 14.0–21.5 | draft：drop 上 ZMark 亮相，`⌘N` 新建草稿 | 先写，不管存哪 |
| 21.5–30.875 | split：`⌘2` 分屏同步滚动，写 Mermaid 并在 29.0 s 渲染 | 两栏同步排版 / 流程图，本机画出 |
| 30.875–37.25 | dive：灯箱放大，32.75 s 进 3D，36.5 s 回到 300% | 点开，放大细看 |
| 37.25–44.0 | outline：大纲跳转，`⌘S` 首次保存，之后自动保存 | 大纲一键跳转 / 存一次，之后自动存 |
| 44.0–58.8 | finale：`⌘3` 预览，47.75 s 碎片炸开，53.375 s 图标落定，片尾地址 | 纯文本，读来像成稿 |

自查（非独立审查）：标题都对应 0.2.13 已有行为，“之后自动存”依赖默认开启的自动保存（`config.rs` 中 `auto_save: true`）；去掉旁白后片子仍须在静音播放时看懂，用 `snapshot` 只看画面检验；音乐的拼接点必须同时在两个片段的小节线上，渲染后用 `hyperframes audio` 核对。
