# ZMark 第三期宣传片：故事线草案

修订：r1，2026-11-20。状态：草案，待用户选择。

## 共同前提

- 时长 60–75 秒，16:9，母版 1920×1080、60 fps；简体中文旁白，英文版后续复用分镜另出。
- 旁白是时间基准：画面文字落在说出它的词上，但不逐字重复旁白。
- 产品画面来自 ZMark 实际界面、源码图标和主题色；功能名和快捷键以 0.2.12 源码为准。
- 3D 只用于生成内容（Markdown 符号、Mermaid 节点、纸页、Logo），ZMark 窗口和控件保持正视、不倾斜。
- 前两期的完成状态：《写下去，读得顺》在 `promo/zmark/`，《光速成稿》（35 秒，无旁白）在 `promo/zmark-v2/`。

## A. 《今晚要发版》（推荐）

**手法与形式**：用“某人一天里的一个时刻”讲故事，配合一镜到底。开发者晚上要写发布说明，ZMark 从一份空白草稿带他走到可发布的文档。观众会跟着一件真实的任务走，感到的是“少操心”。

- **开头 2 秒**：深色桌面上方悬浮一个 3D `#` 字符，旁白说“十点，发布说明还是空的”；`#` 落进窗口，变成草稿的第一个标题。
- **节拍**：钩子（深夜任务）→ 卡点（文件散在文件夹里，草稿还没决定放哪）→ 揭示（ZMark 名称）→ 证明（新建草稿、分屏同步滚动、Mermaid 灯箱、大纲跳转、首次保存选位置并开始自动保存）→ 高潮（Mermaid 流程图从二维展开成 3D 节点穿过镜头，再回到预览）→ 主张 → 片尾。
- **画面**：从石墨夜色到 ZMark 浅色工作台，用琥珀橙标注当前操作；3D 物件使用纸面质感和低饱和反光。
- **声音**：Lo-fi 电子乐，约 90–100 BPM；揭示处进鼓，高潮前留 0.5 秒静音；点击、按键和保存只在画面动作上出声。

## B. 《一份 Markdown 的旅行》

**手法与形式**：用“一个物件穿过不同场景”讲故事，场景之间逐个物件衔接。一份 `release.md` 从 Finder 拖进 ZMark，在预览、灯箱、大纲和导出的 HTML 页面之间流动，观众记住的是“同一份纯文本，处处读得好”。

- **开头 2 秒**：一张 3D 纸片从 Finder 列表里翘起，旁白说“这只是一个 `.md` 文件”。
- **节拍**：钩子（纯文本文件）→ 卡点（源码难读）→ 揭示 → 证明（拖入、分屏、`[toc]`、表格、Mermaid、导出）→ 高潮（纸片折成浏览器里的 HTML 页面）→ 主张 → 片尾。
- **画面**：每个场景有不同光源和比例，纸片是贯穿的视觉线索；3D 只出现在纸片折叠和片尾。
- **声音**：明亮钢琴与轻打击，约 110 BPM；每次换场使用不同的纸张声或转场声。

## C. 《Markdown 之城》（大胆版）

**手法与形式**：用“物件本身就是解释”的手法，镜头穿越一个 3D 世界。标题、列表、表格和代码块被搭成一座城市，镜头每停一站，就潜进 ZMark 的真实界面展示对应能力。

- **开头 2 秒**：镜头从 `# ZMark` 塔顶俯冲，旁白说“每份文档都有结构”。
- **节拍**：钩子（城市俯冲）→ 卡点（结构在源码里看不见）→ 揭示 → 证明（城市里的四个站点分别进入预览、表格、Mermaid 和主题）→ 高潮（整座城市折叠成大纲）→ 主张 → 片尾。
- **画面**：Three.js 夜景，琥珀色街灯，真实 UI 只在正视镜头中出现。
- **声音**：电影感合成器，约 100 BPM，高潮处有一次上升音效接重击。
- **代价**：3D 资产和逐帧渲染最多，制作与审片时间约为 A 的 2 倍。
