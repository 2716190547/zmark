## 已确认的产品选择

- 源码围栏代码与预览共用语言感知的语法高亮，不再用整块统一墨色代替结构区分。
- 首期验收 XML/HTML、Java、Python、JavaScript、JSON、YAML、SQL、Shell、Rust；未知或未支持语言回退普通代码色，不误称已支持。TypeScript/TOML 不作本批专项保证。
- 无语言及 text 围栏保持纯文本，不自动猜语言。保留现有代码换行规则：非空且非 text 的语言块换行，空语言/text 横向滚动，Mermaid 独立处理。
- 默认与 Claude 使用暖米灰代码背景、低饱和紫色标签/关键字、金色字符串、灰色注释。其他六套调色板保持自身风格，全部适配明暗；正文颜色与字体不随代码主题修改。
- 显示实际本地 Markdown 图片，支持相对文档目录和绝对文件路径；本批不增加网络图片请求。按可用宽度保持比例，加载失败才显示占位及原因，不把占位视为加载成功。

## 已证实的灯箱根因

实际生产链路：

```text
预览 img(path)
  → 文件资源 ImageAssetLoader
  → SVG render_pixmap
  → swap_rgba_pa_to_bgra

灯箱 img(ImageSource::Image(Image::from_bytes(Svg, ...)))
  → ImageDecoder
  → Image::to_image_data
  → SVG render_pixmap
  → 直接把 RGBA 预乘像素作为 BGRA 的 RenderImage
```

GPUI 0.2.2 本地源码：`elements/img.rs` 的 ImageDecoder::load 直接调用 to_image_data；文件资源 SVG 分支才执行 swap_rgba_pa_to_bgra；`platform.rs` 的 ImageFormat::Svg 分支没有通道交换或 alpha 还原。Phase G 更换 API 仍回到同一错误解码路径，之前 ADR 与验收对“新路径会自动转换”的判断不成立。

最小实际解码对照已运行，SVG 含不透明 `#9370db` 和 60% alpha 的 `#ecf2dc`：

| 像素 | 字节 Image 路径（当前灯箱） | 文件路径（当前预览） |
| --- | --- | --- |
| 紫色 | [147,112,219,255] | [219,112,147,255] |
| 半透明浅绿 | [142,145,132,153] | [219,241,236,153] |

两路应为同一 BGRA 颜色，但真实返回不同；测试红灯并直接比较实际 RenderImage::as_bytes，不是源字符串或 API 名称断言。

诊断产物：`/private/tmp/glidemark-color-probe/color_probe.rs`、`result.log`；已编译运行命令 `/private/tmp/glidemark-color-probe/color_probe --nocapture`，结果 0 passed / 1 failed。这是生产使用的 GPUI 两种解码入口对照，不是完整灯箱 UI 截图测试。

深浅 SVG 选择、HiDPI 缓存、图表源 classDef/style 和卡片底色也需回归，但不能用它们掩盖上述已证实的像素错误。第三张附件日期为 11-02，仅作为现象参考；当前真机窗口读取超时，尚未完成新版本视觉复现。

## 其他事实

- 预览 render_code_block 只设置 syntax_code，StyledText 仅加选区背景，没有语言词法着色。
- 源码 tokenize_code_line 只有通用关键字/引号/注释猜测，未接收围栏语言，不识别 XML 标签、属性及跨行语法状态。
- Markdown Image 分支始终渲染图标和 alt/url，占位不是本地文件找不到的充分证据；当前没有普通图片实际加载链路。

## 工单与验收顺序

### I0：先闭环灯箱像素

将当前红灯对照固化为永久回归，在真实 open_lightbox 所用的加载结果上检查不透明色、半透明色及合成底色。优先复用已转换正确的 GPUI 公共文件资源解码，不新造手动颜色转换；如采用其他实现，必须以真实像素证明等价。

先验证所选加载方案能同时管理缓存和 GPU 纹理释放，再替换生产路径。现有资源释放仍必须成立：关闭、文档切换、图片替换均释放旧纹理及资产缓存。不要为修色放弃显存回收，也不要假设 GPUI 文件解码的内部缩放不会扩大 HiDPI 纹理预算；检查真实解码尺寸与最终内存预算。

同一原始 Mermaid SVG、当前明暗变体、自定义颜色和透明度在预览与灯箱保持一致，不通过改 SVG 源色抵消通道错误。热缓存、重开、切主题、切文档和不同屏幕倍率均应正确。像素检查通过后补真实应用视觉对照，记录能实测与不能实测的部分。

### I0 补修 #1：真实解码预算与加载所有权

独立验收确认：元素实际加载的资产像素与预览一致，改回错误 ImageSource 路径后三个像素检查变红，跳过缓存/纹理释放亦变红。此成果必须保留，不退回旧通道，也不继续泛改主题颜色来处理显存问题。

P1 根因：文件 SVG 加载器固定使用 `SMOOTH_SVG_SCALE_FACTOR=2.0`，现有 `calculate_hidpi_dimensions` 却按屏幕 effective_scale 限制 SVG header。sf=1 时 header 4000×2666，实际 RenderImage 为 8000×5332，单张约 170.6MB；每档面积均为旧路径的 4 倍。预算必须作用于实际解码结果：最大边不超过 4000px、总像素不超过 16,000,000，保持比例及合理清晰度，不能只检查 header、扩大上限或取消 HiDPI。

先对真实 open_lightbox 与元素实际加载的 RenderImage::size/as_bytes 建立超限失败检查，再修加载尺寸换算；覆盖 sf=1/1.5/2/更高倍率、超宽/超高图和热缓存。缓存需区分旧算法生成的超限文件，不能命中旧产物后仍绕过新预算；回退尺寸修复必须使预算检查失败。

关联项同轮收口：

- 独立灯箱资源和预览共享资产的所有权。fallback 共用路径时，关闭/替换灯箱不能清除仍被预览使用的资产或纹理；同时不得漏掉灯箱独占资源回收。
- 创建目录/写入 HiDPI SVG 失败时，不缓存不存在的文件，也不将其作为显示源；回退到可用源或明确显示失败，不能无声空白。
- 去掉仅为旧测试保留的 hidpi_image/Image 双通道死状态，按实际生产路径适配检查，不为兼容无用分支增加抽象。
- 像素检查应证明元素已加载，避免 get_asset 隐式启动加载后测到一份测试自解码的正确副本。明暗样本采用可区分的实际色值，锁定正确变体；图已打开时主题改变须刷新对应源或采取明确一致的状态处理，不能停留错误变体。

保留实际颜色、合成透明度、资源释放及 Phase H 的默认与 21 项专项回归。代码提交后再打包，报告真实 RenderImage 尺寸、像素数/字节数、screen scale 与 decoder scale 换算、失败和回退证据；I0 未通过前其他工单继续等待。

### I0 补修 #2：锁定元素实际加载的颜色（规划已审通过）

### I1：共用语法解析与色彩语义

本节及 I2/I3 的技术方案已由 Reviewer 对 e6a3e6a 签字，产品选择沿用用户确认；此处是规划批准，不是实现验收。

仓库没有现成的语言解析依赖。方案优先采用成熟 Rust 语法库 syntect，复用其内置语法；采用最小必要 feature，不加载无关主题/HTML 导出/运行时语法文件，不手写九套语言词法规则。纯 Rust regex 后端可避免新增 C 编译链，实际性能在接入前测量。

依赖明确为 syntect 5.3 系列、关闭默认 feature，仅启用 `default-syntaxes`、`regex-fancy`（前者已包含 parsing）；不启用 default-themes/html。语法集合加载一次，在后台准备，不把首次初始化放到 render 热路径。

语言标签取 info string 首个空白分隔 token、trim、ASCII 小写，再查静态的有限 canonical 表：xml→XML，html/htm→HTML，java→Java，python/py→Python，javascript/js→JavaScript，json→JSON，yaml/yml→YAML，sql→SQL，shell/sh/bash→内置 Bash 语法，rust/rs→Rust。必须在实际内置 SyntaxSet 上验证这些名称/扩展映射；不依赖未核实的显示名称拼写，不通过文件首行猜语言。空标签及 text/txt/plain/plaintext 返回 Plain；其他语言本批也回退 Plain（zsh 不冒充完整 Bash/Zsh 支持，TS/TOML 不新增语法包）。

syntect 的 find_syntax_by_token 已按扩展名和大小写不敏感名称查找；映射表的用途是统一产品支持集合与缓存身份，不声称 py/js 一定无法由库直接识别，也不重复实现语法查找器。

官方依据：[syntect 文档](https://docs.rs/syntect/5.3.0/syntect/)、[feature 列表](https://docs.rs/crate/syntect/5.3.0/features)、[项目说明](https://github.com/trishume/syntect)。TypeScript/TOML 并非内置包的专项保证，本轮不额外添加语法集合。

源码与预览共用语言及带范围的语义结果；支持跨行注释/字符串/嵌套语法状态，XML 的 tag、attribute、string 不混为一色。复用 ThemeColors 的关键字、字符串、注释色，按需要补充属性/数字等最少语义。未知范围回退代码普通前景。

共用数据契约放在 `glidemark_core::syntax`：`SyntaxRole { Plain, Keyword, Attribute, String, Number, Comment }` 与 `SyntaxSpan { range: Range<usize>, role: SyntaxRole }`。range 是相对于完整 canonical 代码 payload 的 UTF-8 字节半开区间；合法边界、按起点排序、不重叠、合并相邻同角色，Plain 补齐空隙，拼回 canonical 字节必须完全相同。canonical 选择 parser 的代码事件文本（LF 及其补充尾换行），源码 CRLF/前缀等另用逐行源映射投影，原文件、编辑和源码复制不改字节；不能把 canonical offset 当源 offset。此选择属于末节待复审修订，替代先前“payload 本身保留真实 CRLF”的矛盾要求。输出不含 GPUI、主题色或字形样式。

编辑端的围栏信息必须保留语言、物理行范围及每行 payload 到原缓冲区字节范围的映射；复用现有 pulldown-cmark 及源范围能力，不另写一套完整 Markdown 解析器。扫描 fence 语言/闭合位置变化后重建受影响代码块信息，不能只保留 bool。共用内核按整块从起始 ParseState/ScopeStack 连续处理各行，跨行字符串/注释不得每行重置；源码再将整块 spans 映射到物理行与视觉子行，预览直接使用同一 payload spans。未闭合围栏按当前文档结束处理，修改闭合位置不得把旧块状态泄漏到相邻块。

仅改文字前景与代码背景，不额外改变字体、字重、行高或插入内边距。高亮范围必须使用合法 UTF-8 边界，软折行、选区叠加、纯文本复制与实际点击几何不变。

解析按文档/代码内容及语言复用，多行语法正确失效，不在每个 render 或每次滚动解析整篇。设置合理预算及失败回退，避免恶意或巨大代码块阻塞 UI；异常时显示原代码，不能丢内容。验收相同语言代码在源码与预览中得到一致语义和颜色，不能只有 helper 正确而两侧生产入口未接通。

具体降级规则：单块超过 64KiB UTF-8 字节、2000 个物理行或任一行超过 1000 个 Unicode scalar 时，整个块返回 Plain，原文字仍完整显示。不采用“只解析前1000字然后继续下一行”，避免多行状态失真。解析错误或预算耗尽同样整块回退，不截断正文。边界等于上限允许解析，空行/末尾换行计数规则由用例固定。

缓存按 canonical language + 完整原始代码身份共享，命中除 hash 外核对实际内容；role 结果不含颜色，因此不把 theme_id 放入解析缓存键，切主题只重新映射颜色。e6a3e6a 原批准最多 32 块且 span/代码缓存合计上限 4MiB（实际容量），语法集合单例另计；固定条数与可见块恢复的冲突现按末节候选修订复审，尚未批准新实现。每个 Workspace 最多一个解析任务和一个最新待处理请求，重复内容合并；请求带文档身份、revision、语言与代码块身份，旧结果不得回写。

后台任务在行间检查取消及累计 50ms 软预算，超过则回退整块 Plain；单次 regex 调用不可强行中断，不能声称这是硬实时终止保证。执行器必须有界，不能每按键新建无界线程，UI 在结果未就绪时用完整 Plain 文本。Reviewer 在复审中核验这组输入/regex 限制是否足以控制单行长尾，有反例先改规划，不让实施端擅自放宽阈值。验收冷解析、滚动零重解析、普通编辑失效范围、围栏状态传播及主题变化复用。

### I3：本地图片实际加载

在后台通过文件句柄做大小预检及最多 20MiB+1 的有界读取，取得不可变字节快照，后续校验与加载必须使用该快照生成的私有缓存源，避免 header 检查后 GPUI 重开原路径遇到文件被替换。复用 Cargo.lock 已有 image 0.25.10，作为必要的直接依赖只声明 PNG/JPEG/GIF/WebP 所需 feature；不新增 C 解码器或手写 header 解析。

SVG 不能走 image_dimensions。复用已锁定 usvg 0.45.1 读取实际 size，解析时关闭 image href 的外部及嵌入位图解析；本批不支持 SVG 内嵌位图/外部图像，需明确报错，不能悄悄缺图。校验通过的原 SVG 字节生成私有快照，最终文件资源加载仍计 GPUI 的 2× SVG 解码倍率；若实际解码将超限则错误占位，不自动缩图。需验证解析不会提前解码被禁止的嵌入图片，保持文字/font 渲染与既有 GPUI 行为一致，不因为 metadata 探测重写丢失文本。若这些公开 API 条件不成立，先返回规划讨论替代方案，不能把 SVG 当普通位图或直接跳过检查。

Workspace 将 `self.state.doc.path` 及文档身份传入预览上下文，路径解析为独立可测试函数：本机绝对路径直接使用；相对路径以文档父目录 join，允许正常 `../` 引用，不强制限制到工作区；草稿无目录仅相对路径报“未保存文档无法解析相对路径”。本批仅普通路径，不承诺 file://、data: 或其他 URI scheme；http/https 明确不加载。URL fragment 先按引用语义分离，再只做一次百分号解码（复用已锁定 percent-encoding），校验 UTF-8/NUL；文件名含 # 等保留字符使用 %23 等转义；不把 + 当空格，带查询串的本地引用给出明确不支持。中文和空格路径保留，不用进程 cwd 兜底。
