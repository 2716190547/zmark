## 1. 已确认的用户决策

- 主场景是**日常编辑**：输入、双栏预览、切换文档、空闲驻留；大文件与媒体密集文档用作边界保护，不主导架构。
- 允许讨论低价值功能删除，但当前基线**保留全部现有用户功能**：编辑、文件内查找、文件名搜索、导出、图片、Mermaid、灯箱、更新、调色板、语言与文件管理。
- 删除有证据的死代码和旧接线，不等于删除用户功能。旧 Mermaid 数据模型/解析器仅被自身测试调用，已同意列入删除项。
- 动效尽量不打折扣：优先复用 GPUI/已安装组件的动画、展开和生命周期能力；没有合适替代时保留必要自定义实现，不直接静态化。
- 外部文件变化采用**保存前校验＋窗口重新激活时检查**，不建设实时监控或常驻轮询。沿用 DocumentStatus 与现有冲突交互。
- 本次大工程特别采用**阶段相关测试＋最终候选全量一次**。先隔离测试环境，再建立基线；不要求每次微小编辑都全量。
- 单代理、单一写入者、在 `dev` 工作；不 push、建 PR、发布或改写历史。

## 2. 审查口径与当前事实

### 使用负载

按单人本地桌面应用评估，不按服务端多租户评估。建议基准固定为 1200×800 窗口、默认调色板、Source/Split/Preview 三模式、普通中文 Markdown、少量代码块/图片、多个文件切换。加入 1.5 MB 文档、CRLF、emoji、IME、多列选区、大量匹配等边界输入。

同一文件可能被外部编辑器、Git 或同步工具修改，这是实际数据安全边界，不因“单用户”忽略。

- workspace 为 `zmark_core`、`zmark_app`、`release_tool` 三个 crate。前两个是运行应用；第三个是发布签名工具，不计入编辑器常驻架构，不为了“两个 crate”删除它。

- `crates/*/tests`：67 个 Rust 文件、17,986 行。
- 静态识别 492 个测试函数（core 90、app 400、release_tool 2）；受 cfg、feature、宏与平台影响，**不是实际通过数或默认运行数**。

## 3. 审查发现

以下编号用于后续指定修复范围。性能候选的重复工作已由代码确认，但**耗时、RSS 和峰值收益尚未测量**。

### Must fix：数据安全与明确错误

### 1. 正文覆盖写入，失败入口静默

位置：`crates/zmark_core/src/document.rs:176-199`；`crates/zmark_app/src/views/workspace.rs:2289-2328,2430-2459`；`crates/zmark_app/src/state.rs:1524-1582`。

- **是什么**：手动保存、自动保存、另存为最终调用 Document.save/save_to。
- **问题**：fs::write 先截断目标文件；写入失败或进程中断可以损坏旧文件。部分工作区入口用 let _ 丢弃错误，用户没有失败反馈。
- **最小修复**：在 core 的共同写入路径实现同目录临时文件→write_all→sync_all→原子替换；参考 config.rs:186-226 的已有模式。成功后才更新路径、last_saved、dirty；所有 UI 入口明确处理失败，不引入 Repository/Service 层。
- **不修的后果**：原文件可能只剩半份内容，自动保存失败也不能及时发现。

验收覆盖原文件不变、编辑与撤销保留、路径/dirty 不提前更新、权限失败、Windows 替换失败、保存期间关闭/重命名。原子替换的权限、符号链接/硬链接语义须在实现前明确；不把临时文件 fsync 宣称为跨平台绝对断电安全。

### 2. 外部冲突处理没有生产入口，重载按钮也没有重读磁盘

位置：`crates/zmark_core/src/watcher.rs:21-68`；`document.rs:202-236`；`state.rs:1165-1235`；`views/workspace.rs:4686-4692`。

- **是什么**：Document 已有磁盘变化/冲突状态，UI 已有保留本地与重载交互。
- **问题**：FileWatcher 只被测试调用，app 没有接入 handle_disk_change。已打开文件的 load_file→open_file 只切换已有文档，重载按钮再次调用它不会重新读取；外部修改可被后续自动保存覆盖。
- **最小修复**：按已确认策略，在保存前和重新激活时检查磁盘内容；复用冲突状态，显式重载调用真正的读盘/冲突解决入口。删除无生产用途的 watcher 及其专用测试/直接依赖前，核实没有其他真实用途。
- **不修的后果**：冲突测试通过不代表应用保护生效，用户可能覆盖另一编辑器的修改。

注意：脏活动编辑先同步后判定冲突；后台自动保存也检查对应 DocKey，不只检查活动文件。保留本地需要对用户已确认的磁盘版本做明确确认；确认后再次外部修改应再次拒绝覆盖。无跨进程协作锁时，校验与替换之间仍有竞态，不宣称完全消除竞争写入。

### 3. 创建新文件的命名检查与写入之间可覆盖外部文件

位置：`crates/zmark_app/src/state.rs:1393-1410`。

- **是什么**：通过 Untitled.md、Untitled 1.md 等递增命名避免同名。
- **问题**：exists 检查后才 fs::write；另一进程在此间创建同名文件，应用会截断其内容。
- **最小修复**：使用 std::fs::OpenOptions::create_new(true)，只在 AlreadyExists 时递增重试，其余错误直接返回。
- **不修的后果**：共享目录或外部工具同时建文件时发生数据丢失；顺序创建的测试发现不了。

### 4. 导出链接只做 HTML 转义，没有协议校验

位置：`crates/zmark_core/src/export.rs:145-157`。

- **是什么**：把 Markdown 链接写成 HTML href。
- **问题**：转义引号不能阻止 javascript: 协议；导出含 `[open](javascript:alert(1))` 的外部文档后，点击链接可执行脚本。
- **最小修复**：在导出信任边界过滤危险协议，保留 http/https/mailto、锚点与安全本地相对路径，失败时输出链接文字。只增加小型校验和恶意输入检查，不引入通用 HTML 框架。
- **不修的后果**：导出本地文档会把主动脚本链接带给读者。

不借此改动网络图片策略或实现完整 HTML 富文本处理。该项是安全修复，不冒称性能优化。

### 5. 旧侧栏关闭计时器可结束新的动画

位置：`crates/zmark_app/src/views/workspace.rs:2209-2238`。

- **是什么**：关闭侧栏后等待 180ms 再卸载内容。
- **问题**：0ms 关闭、50ms 打开、100ms 再关闭；第一次回调在 180ms 看到 drawer_closing=true，会提前截断第二次关闭。bool 不区分哪次动画。
- **最小修复**：优先使用现有组件的可逆展开/退出状态；原生等价替代不可行时保存并取消旧 Task，或以精确代际防旧回调，保持现有时长与效果。
- **不修的后果**：快速切换时闪断、反向展开不连续；不应靠延长动画掩盖。

### Should fix：基线可信度、重复成本与维护负担

### 6. 部分测试读取正式配置与工作区

位置：`crates/zmark_app/src/state.rs:458-460,483-546`；`tests/app_editor/stage_a_rework_test.rs:77-83`；`tests/phase_h_b1_real_geometry.rs:71`；`tests/phase_i_syntax_and_warm_palette_test.rs` 多个 fixture。

- **是什么**：测试直接 AppState::new，加载本机偏好并扫描 workspace_roots。
- **问题**：字号、侧栏根目录、自动保存等用户配置影响布局、耗时和副作用；相同提交在不同机器不能可靠对照。
- **最小修复**：复用 new_isolated/new_with_preferences_at，临时目录由测试持有；需要真实设置的测试显式指定临时偏好。不用并行 set_env 改 HOME。

### 7. 旧查找契约已变，复制路由测试可能恒真

位置：`tests/app_editor/stage_a_rework_test.rs:77-145`；`stage_b_preview_interaction_test.rs:88-143`；`tests/phase_h_b4_cmd_c_routing.rs:138-154`。

- **是什么**：验证输入焦点转移和搜索框复制权。
- **问题**：旧用例把 Cmd+F 当成侧栏文件名搜索，现生产入口是文件内查找。B4 断言 !(search_focused && copied==Title)，search_focused=false 时即使错误复制 Title 也通过。
- **最小修复**：侧栏测试直接聚焦真实侧栏 Input；文件内查找用真实动作；复制用例输入并选中查询文本，断言剪贴板精确等于查询，保留原焦点隔离保护。
- **不修的后果**：过时测试阻塞正确重构，或错误复制路由在全量中假绿。

本轮未运行，不能宣称这些测试已失败；这里报告的是确认的代码/契约矛盾。

### 8. 普通输入仍重建全文，系统输入查询反复拼全文

位置：`crates/zmark_app/src/editor_engine/editing.rs:65-144`；`editor_engine.rs:270-271,347-348,405-412`；`views/workspace/source.rs:995-1063`；`state.rs:657-665`。

- **是什么**：每次键入通过通用多范围替换，系统输入以 UTF-16 查询文本/选区。
- **问题**：普通一字符插入依次 join 全文、构造更新全文、再 join 撤销快照、split 为全新行列表；系统长度与选区查询另外 join。局部修改的工作量随全文增长，100ms 防抖只延后解析，未避免这些复制。
- **最小修复**：保留同一编辑事务、验证和一次撤销语义；为普通单行插入/删除/替换使用局部路径，复杂多列/跨行仍复用通用路径。系统输入按当前 revision/组合态复用必要快照，优先由行数据直接计算范围；测量后再决定共享行与偏移表是否值得。
- **不修的后果**：日常输入承担无关整篇分配；长文档输入与中文组合输入更明显。

不直接换 Rope，不把普通路径与复杂路径做成两套可写文档真源。删除字符、CRLF、组合输入、emoji、列编辑、undo/redo 都必须保留。

### 9. 隐藏 pane 仍做派生布局

位置：`crates/zmark_app/src/views/workspace.rs:3617-3648,3711-3720`；`views/editor.rs:698-703`。

- **是什么**：Workspace render 统一更新预览尺寸表、可见范围与源码折行。
- **问题**：Preview 模式仍 compute_visual_lines；Source 模式仍 ensure_layout 预览尺寸。修改、改宽或换文档后，未显示 pane 的派生工作仍执行；编辑 pane 每次渲染还重建全篇行偏移。
- **最小修复**：按模式只计算显示 pane 必需数据；大纲/代码映射按实际消费者保留。把已有代际边界用于行偏移复用，避免新增大缓存。首次显示隐藏 pane 时精确刷新。
- **不修的后果**：换模式与编辑付出看不到的布局成本；拆文件不能解决它。

不声称 Source 可彻底不解析：源码高亮、代码块范围和大纲仍可能需要 AST。普通文档先保持同步解析；只有 profiling 证明解析超出预算才引入后台解析。

### 10. 媒体渲染路径有重复解码与同步工作

位置：`crates/zmark_app/src/local_images.rs:120-219`；`views/workspace.rs:525-565`；`views/preview.rs:1312-1384`。

- **是什么**：本地图片先受限解码、写快照，再由 GPUI 解码；Mermaid 缓存未命中时渲染 SVG。
- **问题**：raster 图片明确解码两遍，部分格式还重编码；Mermaid 在 UI render 内做解析、目录/文件 I/O，错误没有缓存，每次重绘都会重试。
- **最小修复**：先给 Mermaid 明确的成功/失败结果和文档代际，复用现有后台 Task，把同步工作移出 render；以保留预算、颜色和安全校验为前提，独立验证 raster→RenderImage 直达方案能否删除快照链路。
- **不修的后果**：图片加载增加峰值与磁盘工作，错误图表会重复占用 UI 时间。

直达位图不是无条件实施：先检验真实 Metal atlas 的共享、重复 drop、重用、alpha/BGRA 和灯箱释放。SVG 保留原路径；禁止删除输入字节/像素/帧数/URI 检查来减少代码。失败结果也必须有界并随文档/内容失效。

### 11. 无生产用途的旧代码仍由专用测试供养

位置：`crates/zmark_core/src/mermaid.rs:1-317,324-382`；`crates/zmark_app/src/views/drawer.rs:41-96`；`views/motion.rs:42-49`；`views/editor.rs:573-586,603-619`。

- **是什么**：旧 MermaidDiagram、未调用的 render_drawer 包装、未使用的 motion_delta、旧估算命中/无用参数。
- **问题**：实际 Mermaid 使用 rusty_mermaid::to_svg，旧数据模型只被自己的两项测试调用。包装/旧 helper 没有产品用途，却增加 API 与保护假象。
- **最小修复**：先删除已确认无调用块；旧几何测试逐个与真实 SourceRow/字体命中检查对照。删无用 _is_dirty/_editor_left_offset 参数及其仅供计算的调用，不删仍被错误徽章使用的 on_click_line。
- **不修的后果**：每次修改继续维护早已不用的实现，结构和测试都越来越大。

已精确定位的四块共 **443 行**：Mermaid 317、仅旧解析器测试 62、drawer wrapper 56、motion helper 8。这是可删除块的毛行数，不是最终净 diff，也不保证二进制/RSS 改善；release 可能已经消除了这些死代码。其余删减先证明再估算。

### 12. 重复断言与源码片段断言增加维护成本

位置：`tests/app_state/sidebar_two_tier_and_header_weight_test.rs:8-109,296-310`；`pure_functions_and_wrappers_test.rs:70-123`；`app_media/mermaid_icon_button_test.rs:138-187`；`app_state/header_drawer_polish_test.rs:10-103`；`settings_about_layout_test.rs:12-85`。

- **问题**：mtime 的短用例是更强边界用例的子集；多处重复检查同一主题方法。搜索源码中元素名不能证明按钮接线，函数截取在 impl 方法边界上也不可靠；正常模块搬移会导致无关失败。

## 4. 原生动画能力与最小替代边界

已查看当前安装依赖源码，**未编译 API 实验、未真机验收**：

- `gpui-component 0.9.1::collapsible::Collapsible::motion_id` 已提供可逆 **纵向** measured reveal。适合尝试替换文件夹展开高度手算、from/started 等状态；不能直接替换横向侧栏宽度动画。启用 motion_id 后关闭内容仍保持挂载，必须比较闭合目录树的布局成本，不能仅以减少自定义状态判为更轻。
- `gpui-base 0.9.1::motion` 有 transition、transition_with_status、TransitionState、Presence、Keyframes；只在运行/延迟状态请求帧，支持 reduced motion。
- gpui-component 重导出旧 `animation` 模块，不完整重导出新 motion API。可先使用可直接访问的 facade；如要直接引用已安装 gpui-base，必须证明减少自定义代码/任务，锁定既有版本，不引入第二套新包或只为缩短 import 增依赖。
- 当前 `views/motion.rs::animated` 已调用 GPUI Animation，并在 reduced motion 时跳过包装；它是有价值的短复用，不为了“原生化”再次重写。
- 可逆展开与 Presence 的挂载/卸载语义不同。要保留关闭时不能点击隐藏内容、虚拟行重新挂载、侧栏宽度/标题安全区、180ms/600ms 节奏；不可把组件示例 API 存在当作效果等价。
- 一次性动画重播仍可能需要最小 generation。不能机械删所有计数导致新通知不播放。
- 大纲平滑定位与选区自动滚动属于功能行为，不只视觉装饰；保持同步滚动、手动取消、窗口失活及时停止。优先显示帧驱动取代独立 16ms 计时，仅在实际接线更短且行为等价时采用。
- 不按 Web CSS 假定 GPUI transform/原生窗口动画能力；ADR 0029 的旧版本限制只作背景，实施以当前 0.3.12 API 为准。

## 5. 目标架构：不增加系统，只收紧所有权

维持现有三个 crate，不建立插件系统、事件总线、依赖注入、通用任务框架或全局资源管理器。

```text
zmark_core
  Document / Markdown AST / anchor / syntax primitives / config / export
  小型共同文件写入与校验入口；无 GPUI 依赖

zmark_app
  AppState        文档集合、活动 key、偏好、文件操作
  EditorEngine    活动编辑事务、选区与撤销
  WorkspaceView   窗口事件与组件协调
  source          系统输入、SourceRow 真实几何与编辑事件
  preview         可见块绘制、选区、尺寸表
  local_images    本地图片验证、加载与资源拥有者
  syntax          有界高亮请求/结果
  updater         保留独立信任边界

release_tool      保留签名工具，不参与编辑器运行
```

原则：

1. 不把 5,631 行 workspace.rs 单纯搬成十个文件就称为架构优化。先删除重复入口、无用派生、死状态；只有真实职责需要独立维护时才搬出 lifecycle/media/scroll 等 impl 分片。
2. 同一个编辑事务更新 revision/dirty；活动 EditorEngine 是输入真源，Document 缓冲在解析/保存/切换等读取前同步。非活动文档由各 OpenDoc 持有。不新增可绕过事务的第二套写入口。
3. 输入绘制、光标、点击、UTF-16 与选区复制仍走同一几何与范围约定。
4. 异步结果只带必要快照和 DocKey/revision/request id；最多一个活动＋一个最新待处理请求用于真正需要的管线。避免为每种功能统一一个“大调度器”。
5. 不合并所有缓存。对每种资源明确 wanted/loading/ready/retired/释放时机，沿用各自预算，不靠扩大预算换性能。
6. 预览→workspace 的共享 Tooltip 类型等依赖先用已有局部 Tooltip/组件消除；不为了完全单向 imports 拆出额外 View/entity/trait。
7. Windows/macOS 的原生文件替换、垃圾箱与签名差异保留，不抽象掉安全措施。Linux 不借机重写。

## 8. 性能与资源验收方式

不预设“内存下降 50%”“120fps”或强制删行比例。指标分别评价：

- **输入**：单字符、换行、跨行/多列粘贴、undo/redo、中文组合查询；同一次操作总分配和 UI 处理耗时 p50/p95。
- **布局**：Source/Preview/Split 初次与热切换、拖宽、可见项数量、重新 shape 行数；帧探针只代表其回放场景，不能冒充输入延迟。
- **空闲**：稳定 RSS、Physical Footprint、CPU 与无交互时是否仍请求帧；分别记录，不把单次 ps 样本当基准。
- **峰值**：编辑/切换、图片加载、灯箱缩放及关闭/隐藏后回收。CPU buffer、GPU atlas、临时文件、syntax/undo cache 不能互相替代口径。
- **构建/测试**：冷编译、增量编译/链接、热执行、默认与 feature 专项分别计时；保持构建条件和 target 缓存，不清空 `/Users/apple/zmark-target` 造冷基线。
- **统计**：至少三次重复，同场景同版本配置；记录波动。有明显回退则分析或回退对应阶段；性能持平但代码确实更少可按维护收益交付。

bench_memory.sh 当前使用正式配置、只采 idle RSS，并只在二进制不存在时构建；不能直接作本次受控对照。frame_probe 当前回放模式动画，不能验证所有输入/媒体问题。最小隔离 harness 只服务本次验收，复用已有入口，避免新的通用性能平台。

## 9. 自我挑刺：必须显式保留的限制

1. **静态审查不是基准或全量通过**：492 是静态函数数；本轮测试执行 0、性能回放 0。所有性能改善待 P0/P3/P4 证明。
2. **保存原子性不等于外部事务**：保存前内容校验不能彻底阻止另一程序恰好在检查后写入；不引入跨程序锁协议，明确其窄竞态。
3. **原子替换改变 inode 语义**：权限/硬链接/符号链接/Windows 分享锁行为必须验证，不能直接拷贝 config 写入就宣称正文等价。
4. **局部编辑可能反而增加状态**：先用最小单行路径；必要快照以 revision/组合态失效，禁止成为第二份无限寿命全文缓存。
5. **隐藏 pane 不代表无人消费 AST**：大纲、高亮与 list continuation 仍需范围；只删除确认无人使用的派生，不能粗暴停止所有 Source 解析。
6. **原生动画不一定更轻**：Collapsible 是纵向 reveal，不能直接做横向侧栏；启用 motion_id 的关闭内容仍保持挂载。如果增加闭合树的布局成本或改变虚拟化语义，保留简单原实现并修 race。全局样式/效果尽量不变。
7. **直达图片是高风险可停项**：旧 ADR 的 Metal atlas 风险是旧版本证据，当前版本需重验，不能当作永久禁止，也不能忽略；性能收益不得以丢色/漏释放换取。
8. **默认与专项不能随意去重**：不同 feature 可能改变观测与 mock 行为；先维持约定门禁，不根据数字相同就跳过。
9. **删死代码不等于减 RSS**：release 可能已 dead-strip。只把验证到的运行工作/持有量减少写入性能结论。
10. **审查范围不是无限**：完整实现前还需阶段相关调用链深读；发布更新协议不做大改、GPUI 原生输入不整体替换、跨平台实机与真实 GPU 像素仍需单独验收。
