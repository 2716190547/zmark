## 已确认的用户选择

1. 预览代码块的字号与行距跟随普通正文，代码继续使用等宽字体。比较对象为普通段落实际字号及行高（当前分别为 `base_font_size` 和 `1.75`），不扩大为全局统一标题、表格及列表样式。
2. 预览栏始终显示滚动位置，支持拖动和点击；短文不足以滚动时仍显示合理的不可操作轨道/滑块，不拦截正文选区。用户接受未测区域按文档顺序近似定位，块高度不同时比例并非精确，优先保证性能及到达首尾。
3. 编辑器行号减淡，并收紧行号与正文间距；必须保持行号可读及长文档数字不截断，抽屉打开时正文起点与标题视觉对齐；抽屉关闭时按 ADR 0029 优先保证 macOS 红绿灯安全区，不要求以遮挡换取对齐。
4. 截图中的 Windows 绝对图片引用需要修复入口。仅在 Markdown 文档所在目录及其直属 `assets` 子目录中查找同名普通文件，不递归、不扫描工作区其他目录或主动请求 HTTP/URI；多处同名时向用户展示候选并由用户明确选择，找不到则给出手动处理提示。只有明确点击后才把当前这一处引用改为相对路径，作为可撤销的普通文档编辑；不新增直接保存，但遵循现有自动保存配置：开启时可延时自动写盘，关闭时手动保存；不自动或批量修改原文。
5. 内存以同文档、窗口、操作和统计口径做前后比较，优先降低稳定占用与峰值；同时记录 macOS Physical Footprint 和 RSS。现阶段不预设 300 MB 等没有同场景证据的固定门槛。
6. 清理代码、老旧测试和遗留文件，并进行 ponytail-review；只删有证据的失效、重复或无调用项，保留历史行为保护，不靠 ignore、降低断言或删除生产仍需的测试凑数。

## 事实与基线

- 用户当前进程（release，PID 83826，约运行 15–21 分钟）的单次 `footprint`：Physical Footprint **359 MB**，历史峰值 **442 MB**。系统分类包括 Malloc Small **140 MB**、Malloc Large **52 MB**、IOSurface **88 MB**、IOAccelerator graphics **61 MB**；它们是内存区域分类，不是对某个函数或泄漏的归因。`ps` RSS 约 **386 MiB**，与 Physical Footprint 为不同指标。
- 截图文档只读核对约 **246,661 bytes、6976 行、23 个 Markdown 图片引用**，其中两处 Windows 绝对路径。截图所指同名图片在该文档直属 `assets` 有一份。此文只记录统计，不提交用户文档、图片、绝对路径或私有内容。
- 独立临时进程加载该文档副本及只读链接的 assets，8 秒后采样 3 次：Physical Footprint 均 **118 MB**、RSS 均 **184,592 KiB**。该进程只停在初始视图，其窗口、滚动、编辑、打开文件历史与用户运行进程不同，不能把两者差值直接当成泄漏或优化收益。临时进程已退出，用户进程未被关闭。
- `scripts/bench_memory.sh` 的现有 release 基准：默认示例峰值 RSS **152.0 MiB**；1,500,012 bytes/16,546 标题合成文档峰值 RSS **219.4 MiB**，8 次采样。它是辅助对照，不代表用户实际文档与 Physical Footprint。ADR 0026 的 `<300 MB` 是特定大文档 RSS 历史门槛；ADR 0022 的历史数字是 Physical Footprint，不能直接混比。
- `editor.rs` 的 36px 行号宽、12px 间距与实际 div 样式重复表达，`EDITOR_TEXT_START_OFFSET` 及标题、点击、光标、折行/布局链路依赖其组合。`preview.rs` 普通段落为字号 1.0、行高 1.75，代码块为字号 0.85、行高 1.5，命中 region 中也记录同一旧值。
- GPUI 0.2.2 的 `ListState` 已提供滚动条拖动起止、按像素偏移设置及当前/最大偏移查询；最大偏移基于已测量内容。`measure_all()` 会测量全部项目，默认不采用以免破坏虚拟化与大文档预算。未测量项目高度实际为 0，API 本身不提供全篇高度估算。实测 1000 个高度不等项时，直接按已测最大偏移拖到底仅至第 3 项；`scroll_to` 定位末项后顶端约第 983 项且末项可见（完整探针 `/tmp/glidemark-phase-j-scroll-probe.rs` 与 `/tmp/glidemark-phase-j-list-probe.log`）。用户已接受文档顺序估算，中间位置非精确像素比例。parser offset 临时探针也证实：两个相同内联图片有不同事件范围；引用式图片的事件范围仅覆盖 `![alt][id]` 而不是定义，解析后的目标也可能已去除括号转义，因此不能在解析后 URL 中查找原始目标（匿名探针和日志位于 `/tmp/glidemark-phase-j-image-probe.rs` 与 `/tmp/glidemark-phase-j-image-probe.log`）。
- 初步 ponytail 候选：`glidemark_core::syntax::MAX_CACHE_ENTRIES` 仅有声明、没有调用，旧 32 块常量与现在按字节准入不一致；可删除并保留 4MiB 字节预算回归。行号几何重复数值应统一真源。代码块帧内字符串复制可能是短暂分配；尚无证据它是当前常驻占用或主要根因，须测量后再决定。

## 实施与验收边界

### 排版与滚动

- 缩减行号视觉权重、按实际最大物理行号和字体测量安排足够宽度，避免固定窄宽截断 4/5/6 位数字；标题、行号实际布局、正文起点、折行、光标与鼠标命中使用同一几何口径。保持深浅主题下可读；对抽屉打开时实际标题/正文坐标进行测量，覆盖 Source/Split、抽屉动画、字号及缩放。抽屉关闭或全屏时优先遵守 ADR 0029 的红绿灯安全区，记录可见的对齐取舍，不只比较 helper 常量。
- 代码块按普通段落实际字号和行高设置；`TextRegionInfo`、测量、滚动及高亮/选区几何同步，保留长代码横向滚动、复制按钮、结构化着色及两侧一致性。对普通段落、代码、表格、列表、中文及混合宽字符，用真实渲染和鼠标事件检查选中范围与复制一致。
- 使用 `ListState::logical_scroll_top` / `scroll_to(ListOffset)` 对整个文档按块顺序作粗定位，明确大小不等块的误差；当前块已知高度时以块内像素偏移反映局部进度，单个超长块不得把滑块固定成不可动。首尾显式锚定真实首项和末项，使新文档直接拖到底可达末尾；不以 `max_offset_for_scrollbar` 冒充未测全文高度，不调用 `measure_all()`。拖动期间冻结映射所用快照，释放/失活后重取当前状态；滚轮或程序滚动、图片高度变化时以当前列表状态刷新，不能让旧拖动状态覆盖新的滚动。当前 `handle_preview_scroll_wheel` 只由 wheel 事件触发，`scroll_to` 并不会自动触发它；抽出共享的无伪造 wheel 事件的预览到源码同步逻辑，让真实 wheel、轨道点击及拖动调用，保留 `last_scroll_origin` 与 100ms 防回声，合并事件频率并避免每次拖动触发全篇解析。
- 对空文、短文、仅一个超长块、首/中/末、新建时绝大多数项未测量、拖动中高度变化、图片加载、轮滚及程序跳转均验证；测试真实 `deactivate_window()`、`on_mouse_up_out` 和释放后再次拖动。保持分栏同步、文本选择与 Cmd+C 路由，真实鼠标拖动后核实源码侧位置变化，不将轨道覆盖正文。提供无需鼠标的键盘入口：使预览轨道可通过键盘获得焦点，支持方向键、PageUp/PageDown、Home/End，短文按键安全无效；只在该入口确有焦点时消费滚动键，避免冒泡编辑源码，并保持 Cmd+C、输入法及其他快捷键路由。若 GPUI 必须使用独立 FocusHandle，将其限定在轨道且实测不破坏现有共享输入焦点。通过真实键盘事件、Tab 焦点、复制、失焦/重入测试；核实 GPUI 是否能公开辅助功能 role/name，能用则验证，不能用时如实记录 VoiceOver 可感知性限制，不能宣称原生完整无障碍。额外写入按相同几何、非一致块高的真实事件验收；未知高度初次位置为文档顺序近似，绝不显示为精确像素百分比。

### 图片路径恢复

- 原路径识别只覆盖 Windows 盘符绝对路径；在后台查询两个有限候选目录，精确匹配文件名，不读取全部图片数据，不主动发送 HTTP/URI 请求。先以文档目录的 canonical 路径为基准；自动匹配时 `assets` 本身或候选文件若为符号链接则不自动采用，真实候选的 canonical 父目录必须等于文档目录或其直属 `assets`。展示候选相对路径和冲突；点击时重新核对文件为普通文件、设备/文件标识与发现时一致及目录边界，否则提示重试、不修改源文。不能声称用户自行挂载的网络文件系统不会产生系统级网络 I/O；路径检查也不承诺锁定文件在之后永不替换。
- 每个恢复操作携带当前文档身份、revision、嵌套图片 occurrence、parser 在同一 revision `into_offset_iter` 提供的事件源字节范围，以及原始源片段；当前 `InlineItem::Image` 不保存该范围，须贯通 parser、展平/渲染和回调，不能用全局字符串替换相同 URL 的其他出现位置。点击前复核身份/revision、UTF-8 字节边界和源片段；只在源语法能无歧义定位此一次目标子范围时修改，保留 alt 和 title 原始字节。生成文档目录相对的合法 Markdown 目标，覆盖空格、Unicode、`#`、`?`、`%`、括号和转义，且使用当前既有一次解码的语义。
- 当前 `EditorEngine` 没有 range replace，`reset_text` 会清空撤销/重做，因此实现最小单次原子替换：验证原始字节/字符范围，再调用一次 `push_snapshot`，只改目标内容、更新一次 revision，并在 Workspace 走 `sync_from_editor`、`schedule_parse`、可见预览和 `trigger_auto_save` 的既有路径；不得通过 `reset_text` 或循环删除/插入制造多步撤销。现有整篇撤销/重做各受 8MiB 总预算约束，替换前预先检查替换前后两个快照均不超过既有上限；否则不执行修改，说明当前文档过大并提供手动处理提示，既不扩大预算也不静默生成不可撤销操作；该超限处理已由用户确认。覆盖两侧阈值、跨阈、既有撤销历史及 redo 清除。替换前检查当前文档的单一源行和 UTF-8 边界；对其他内容及脏状态不作额外改变。源码光标在替换范围之前保持不变，之后按 Unicode 字符长度差移动，落在替换范围内部则放在新目标末尾；保留其他行的光标位置。现有 undo/redo 只存文本快照、不保存光标历史，因此撤销/重做沿用引擎现有 clamp 规则，不新增光标历史。停止正在进行的预览拖选和自动滚动；预览选区仅在新 AST 同 revision 且对应块/文本仍可验证时保留，否则清除，避免使用陈旧位置。不新增直接保存。自动保存开启时按用户确认沿用既有计时并可能写盘，关闭时手动保存；已有 pending autosave、失焦和切换文档按现有策略处理并验证。对于引用式语法或其他无法无歧义定位单一原始引用的形式，先验证 parser 源范围能力；不能安全定位时保留原文、说明原因并允许手动处理，不猜测或批量替换。
- 用匿名 fixture 验证两处相同原路径只改所选一处、alt/title 内出现同一 URL、嵌套与引用式、多字节/CRLF/括号转义、特殊字符编码、候选冲突、symlink 越界、候选不存在/被替换、切文档或编辑后旧按钮失效、一次撤销/重做、光标位于目标之前/内部/之后及多字节行、旧预览选区无陈旧引用、自动保存开启/关闭/已有 pending 的语义及不发 HTTP 请求。无法无歧义映射的形式只展示手动处理提示，保证原文不变。

### 内存定位与优化

- 保留用户真实进程不关闭、不改变用户文档与偏好；任何交互重放只在隔离配置、隔离工作区及文档/图片副本上执行。当前正式 `main.rs` 调用 `AppState::new` 并读取真实 Preferences 和 workspace_roots，旧 `bench_memory.sh` 也如此，不能直接用于交互重放；已有只读冷启动采样只作为参考，真实文档 mtime 两次核对一致、配置文件 mtime 早于本次基准，但因未事先采 hash 不宣称已验证内容哈希不变。优先复用 `AppState::new_with_preferences_at` 构建最小独立 release 测量入口，把复制的 Preferences 路径及所有 workspace_roots 定向私有临时目录，自动保存只允许落在副本文档上；资源复制到独立目录，不用指向用户文件的可写链接。若必须测正式二进制，先证明操作全程只读或提供等效隔离，不改写 HOME/CODEX_HOME。记录输入原文、资源与用户配置的前后 hash/mtime；原始路径/日志保存在私有临时目录、不进 Git/PR。测量入口与正式启动路径不完全相同，需对照同文档静态启动并报告差异，不能声称完全相同。固定 release 构建、macOS/屏幕缩放、窗口大小、视图模式、文档/资源、初始状态、等待时间和滚动/切换序列；至少重复多次，记录每阶段进程 PID、RSS、Physical Footprint、峰值和系统分类。清晰区分图形相关/共享/可回收内存，不能相加作为对象归因或将峰值当稳定值。
- 先按 `diagnosing-bugs` 构造在受控重放下能复现增量或峰值的快速反馈，再按可证伪顺序排查：①视口变化与图片/Mermaid 资源生命周期；②布局/文本 shape 缓存及帧内重复分配；③语法集与首次 warm、解析和撤销历史；④系统图形缓冲与分配器保留。使用进程快照、受控场景差分及已有工具确认，不能只凭区域分类或现有缓存上限断言根因。当前进程 `heap -s --noContent` 有 259,047 个 non-object 分配共 159,048,581 bytes；此进程未开启 MallocStackLogging，不能据此归因到具体 Rust 类型或调用栈，也不能与 Footprint 分类相加。独立临时进程可短时使用 `MallocStackLogging=1` lite 和 `malloc_history -callTree -noContent` 做存活分配归因；先配对不插桩/插桩测量其开销，绝不把插桩绝对值当正常峰值。只有必要时才在限时、限磁盘且私有的临时目录启用 full 历史，清理诊断产物；不对用户进程事后开启或公开原始含路径日志。
- 每项修复均要说明数据所有权、可回收时机与变化前后效果，并确保颜色、图片解码限制、选区/复制、滚动平滑、缓存安全和大文档性能不退化。不能通过缩小用户文档、降低输入覆盖、关闭高亮/图片或调大预算虚报改善；如果无法复现或没有显著下降，明确报告证据，不编造根因或收益。
