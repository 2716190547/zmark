## 2. 已核对的基线代码与约束

以下记录原代码基线，不代表当前实现状态；A／B 交付及后续组件替换见 §8–10。GPUI 0.2.2 的平台研究不能代替 0.3.12 后端验证。

- `views/lightbox.rs::lightbox_fit_size` 固定使用 800×640；`reset` 只归零平移并设置 zoom=1；HUD 的适应和百分比按钮均调用它。现有 `lightbox_test` 主要检查状态，不证明真实 HUD 事件后的灯箱可见性。**按钮关闭的根因尚未通过失败回归验证，不将阅读代码当作复现。**
- `workspace.rs` 的图表与本地图片最终共用 `render_lightbox`。图表拥有独占 HiDPI 路径，图片和回退 SVG 可能共享；沿用统一释放路径，不能关闭时误删预览资源。
- `state.rs::add_workspace_root` 新增和恢复 missing 根当前均设置 expanded=true；启动恢复由 `normalize_loaded_roots` 负责；打开文档的 `expand_to_file` 另有定位语义。三者不可混改。
- `drawer.rs` 根／子文件夹目前整行点击折叠，箭头仅按终态旋转；树文件仅当前文档双击触发改名，并将输入框放到右侧标题。草稿、外部文件也存在改名路由，不能遗漏。
- `workspace.rs::begin_rename / finish_rename` 只针对 active 文档；`state.rs::rename_file` 只迁移一个文件的路径。扩展目录改名不能靠切换或重新载入文档来重用这一限制。
- 已有 `drawer/search_input.rs::SearchInput` 提供 Enter／Esc、文本选区与中文 IME 输入，优先复用侧栏／标题改名；其 `title_style` 与选择绘制必须随位置正确使用。
- `Preferences::save_to_path` 已有同目录临时写入；Windows 分支目前先删除旧配置再 rename，不能将它当成无损原子替换。目录改名依赖配置落盘前须修复这条共享保存路径的安全性。
- `EditorEngine` 当前没有选区；源码绘制只接点击定位；Workspace 的剪贴板复制仅接预览。源码新行为必须接通引擎、真实绘制、系统输入与焦点路由，不能只添加测试辅助函数。
- 编辑、点击、导航和同步滚动已有真实 `VisualLine`／文字度量缓存，保持虚拟化和缓存预算；不退回字符等宽估算，也不每次鼠标移动 shape 全文。
- `ThemeColors::selection_bg / selection_text / hover_bg` 已被多类组件使用，但搜索／改名输入选区另用文字色 12% 透明度。Phase I 回归明确要求选择覆盖保留语法前景色。
- Windows 控件为自绘 10px 图案、46px 宽命中区；主窗和设置共用 `render_window_controls`，并通过 GPUI `WindowControlArea` 连接系统非客户区事件。这是系统行为路由，**不是原生绘制**。
- GPUI 0.2.2 可提供 HWND，但没有现成原生三键布局控件；Windows 后端自己计算客户区和分发非客户区事件，创建样式也不能假设包含 WS_CAPTION。遵守 ADR 0029，不引入 Web CSS transform 心智模型。
- `.github/workflows/build-desktop.yml` 有 Windows release 构建／打包，但没有 `cargo test` 步骤，也不提供交互桌面验收。当前规划环境为 macOS；没有 Windows 实机通过证据。

## 3. 分阶段实施边界

这是总规划，不是一轮横跨所有模块的实现派发。后续按 A → B → C → D → E 独立推进，一个执行会话只推进一个大任务，同一工作区保持单一写入者；不能只交付 A 就报告全部需求完成。

### A. 灯箱适应窗口及 HUD 关闭缺陷

主要文件：`views/lightbox.rs`、`views/workspace.rs`；回归保持既有独立 `lightbox_*` 目标，不合并到聚合测试。

1. 先通过真实打开入口和 HUD 坐标构造一个秒级、可重复的失败命令，断言点击适应后灯箱仍打开且可见。复现后再定位事件／状态根因；同时检查缩放加减和百分比按钮是否有同类问题。
2. 取原图尺寸和实际灯箱视口，而非固定 800×640。尺寸读取不要发生在每一帧或每次拖动中；复用已知尺寸，必要的元数据只在打开／资源变化时读取。普通图片保留缩小快照之前的原图逻辑尺寸，SVG 区分原尺寸与 2× 栅格尺寸；100% 不使用 1600px 纹理快照的尺寸，也不提高已有纹理预算。
3. 可用矩形扣除卡片内边距、外侧安全留白和 HUD；使用等比 contain。初次打开和点击适应均归零平移。窗口很小、图像横长／竖长、零／非法尺寸和加载失败均有安全回退，绝不除零。
4. 适应模式随视口变化重新计算；用户手动缩放／拖动后保持手动状态，重新点击适应才回适应模式。100% 回原图逻辑尺寸并居中；所有 fit 倍率必须可达，不能被旧的 20%–500% 夹制截断。
5. 图表比例按原 SVG 逻辑尺寸计算，HiDPI 尺寸只决定纹理清晰度。图像缩放沿用 GPUI 布局方式与原有纹理预算；原图逻辑尺寸不等于保证高倍率的像素级清晰度。极小窗口的可用区域不足时采用最小有限尺寸回退，不宣称无法容纳 HUD 的窗口仍可完整显示所有控件。
6. HUD 操作不关闭灯箱、不穿透正文；背景点击、关闭按钮与 Esc 保留关闭功能。保留关闭、替换、文档切换时的独占资源释放和共享资源保护。

验收：真实 HUD 点击回归；不同宽高窗口、宽／高 SVG 和本地图片完整 fit 且不遮 HUD；100%／适应行为可区分；手动操作／改窗口后行为正确；资源和颜色历史回归不变。

### B. 工作区默认收起、600ms 可打断动效和真实原地改名

主要文件：`views/drawer.rs`、`views/drawer/search_input.rs`、`views/workspace.rs`、`state.rs`、必要的共享文件系统／配置安全接缝及 `i18n`。测试放入既有 `app_state` 领域目标，必要配置测试保留在 core。

**折叠与选择**

- 新增以及通过添加入口恢复 missing 根均默认收起；启动恢复维持现有行为。刷新不得擅自展开已收起根；打开文档／搜索的现有定位语义保留。
- 根和子文件夹分别具有约 600ms 箭头旋转／子树整体淡入淡出。无逐项动画、无列表高度动画、无新增动效设置。
- 新指令即时接收，从当前角度和透明度转向新终态，最后一次操作获胜，不从起点闪回。折叠淡出期间保留绘制直到结束；逻辑折叠后子项不接受操作或键盘焦点，结束才移除，不让旧结束回调移除重新展开的内容。
- 动效状态按稳定目录身份区分，仅保留进行中的过渡；删除／改名／搜索改变树时清理过期状态。减少动态效果开启时立即终态并取消剩余动画。
- 箭头和名称分开命中；名称单击选中目录但不切换当前文档，双击只进入该行改名。文件第一次点击可打开，但第二次点击必须识别原目标，不能依赖陈旧的 active 快照；后台文件也能双击改名。

**改名与数据安全**

- 侧栏原地编辑工作区根、内部目录、普通文件、外部文件与草稿；标题入口保留。目标绑定稳定文档身份或实际路径，不因 active 切换而改错对象。
- Enter 确认，Esc／外部点击取消；切换文档、目标被移除或失效时取消。输入默认选择名称主体，文档后缀沿用既有 `.md`／`.markdown` 处理；文件夹不添加后缀。
- 名称必须是单个有效文件名，拒绝空名、`.`／`..`、路径分隔符、路径穿越及目标平台非法名称；禁止更名文件系统根或 missing 目录。仅在原父目录内改名。
- 在共享实际更名入口统一校验磁盘目标与打开文档身份冲突，并使用不覆盖目标的实际文件系统操作，防止检查和 rename 之间的竞态；`exists()` 加可能覆盖的 rename 不足以保证安全。不得为了改名覆盖同名文件／目录。
- 目录迁移按 Path 组件前缀更新全部受影响根、树项、open_docs 的键和路径、active、关闭／改名目标等元数据。保留未保存内容、dirty／冲突状态、光标、选区和撤销栈，不调用 reload 丢弃缓冲区。
- 同步失效旧路径的扫描／搜索／资源异步结果；旧自动保存任务取消，新键继续安全保存原缓冲区。受影响的本地图片按新文档目录重新解析；只局部刷新，不全局重扫所有根。
- 根目录更名后的 Preferences 使用共享安全保存函数。优先去掉 Windows 先删除旧配置的路径，保留同目录临时写入和可替换目标的原子提交；在 Windows 上用失败回归证明原配置不丢失，不凭注释声称原子安全。
- 若根路径落盘失败，使用无覆盖操作尝试回滚磁盘更名；回滚成功恢复旧元数据。若回滚因外部变化失败，以实际磁盘位置为准同步内存并保留缓冲区，明确提示“已更名但配置未保存／回滚失败”，不得复用旧路径自动保存或宣称事务完成。不能通过强行覆盖恢复旧目录。
- 不批量改写正文链接；成功反馈提醒旧名称引用可能需要手动更新，失败清楚显示原因。

验收：真实鼠标双击与 IME／确认取消；新增收起且刷新不展开；600ms 中连续展开→收起→展开最终正确且角度／透明度不跳回；两个目录互不干扰；reduce_motion 中途生效；有未保存子文档和图片的目录／根改名、后续保存与重启路径正确；目标冲突、非法名、权限失败、配置失败与回滚失败不丢内容或覆盖他人目标；搜索旧结果不复活旧路径。

### C. 源码连续／列式选择及常用快捷编辑

主要文件：`editor_engine.rs`、`views/editor.rs`、`views/workspace.rs`；输入边界复用 GPUI 原生 UTF-8／UTF-16、IME、焦点和剪贴板契约。单行搜索／改名直接使用原生 Input；专用源码编辑器不能仅换 element 就删除 `EditorEngine`，需要保留单一事实来源、虚拟化、真实 token 布局、revision／撤销预算及预览同步。组件 `EditorState` 自带 rope／history，未经等价桥接不增加第二份源码状态。测试按 `app_editor` 及既有核心目标归属。

- 源码右键菜单使用组件 `NativeMenu`／平台菜单及既有 actions，复制／剪切／粘贴／全选／撤销共用实际选区；加粗与编号必须接入真实动作和撤销，不把引擎探针当交互完成。解决 Cmd／Ctrl+B 与现有侧栏切换键的冲突。

- 连续选区保存文档锚点和活动端；左键拖选、Shift+点击和 Shift+方向扩选，正反向结果一致。单击重新定位；双击选词，三击选物理行。
- 中键建立按视觉行的矩形选区，包括零宽的多行插入位置。命中、高亮、复制和编辑使用相同真实字形／token／VisualLine 几何，正确处理中文、emoji、Tab、行内代码样式、软折行及滚动。
- 每个视觉行产生真实字符范围，超出短行夹到行尾，空行可提供真实插入位置。重复的同一逻辑插入点去重；软折行不会把同一个字符删除／插入两次。
- 列选复制按视觉行顺序以换行连接，保留行中真实空白和空行，不生成对齐空格。单行粘贴重复，多行行数相等时按行分配；不相等清晰提示且源码、revision、撤销栈及剪贴板内容保持原状。行数计算保留末尾空行，CRLF 作为一个换行处理；普通连续选区粘贴不使用列式数量限制。
- 输入替换所有选中范围，Backspace／Delete 删除所选内容，批量修改作为一次撤销单位、一次逻辑 revision／解析调度／自动保存调度。修改后保留各行的新插入位置，支持继续同步打字，而非仅同步一个字符；普通单击、Esc 或非扩选导航可收敛为活动端的单光标。不增加任意多光标创建方式。维持已有撤销字节预算，不为每行复制整份文档。
- 剪切必须先取得所选原文再删除；复制为原始 Markdown，不混入预览纯文本；全选覆盖文档。Ctrl／Cmd+C/X/V/A/Z 和重做只在实际源码编辑焦点下改变源码。
- 键位按平台约定：macOS Option+方向按词、Cmd+Shift+Z 重做；Windows Ctrl+方向按词、Ctrl+Y／Ctrl+Shift+Z 重做；两平台 Shift 扩选和 Tab／Shift+Tab 使用现有 tab_size 缩进选中物理行。同一物理行只缩进一次，选区恰好止于下一行起点时不多缩进一行。
- 接通系统输入／组合输入替换，避免 KeyDown 和 IME 双重插入。中文组合取消不污染缓冲区；组合提交可整体撤销。列式选择下组合预编辑不提前多处写入，提交时作为一次批量替换。
- 只修改真正持有编辑焦点的源码；预览、搜索、改名、滚动条、模态和灯箱不能误消费编辑键。保留 Phase H 的复制和焦点历史行为。
- 拖选到边缘可继续自动滚动，滚动时锚点不丢失；释放、移出后松开、失焦、切文档时结束拖选。重用已有窗口事件／自动滚动能力，平台不投递窗外事件时明确记录，不能只测试字段清空就声称真机通过。
- 保持虚拟化与真实布局缓存，选择移动不重排全文；修改只让受影响行／语义失效。字号／宽度变化后重新命中，不使用陈旧视觉下标作为修改地址。

### E. Windows 原生三键接入验证与获准替代

主要文件：`platform.rs`、主窗／设置顶栏的共享控件和实际窗口创建入口；必要时将 Cargo.lock 已有的 Windows／raw-window-handle 包提升为目标平台直接依赖。不引入 WinUI／WebView／第二套 UI 工具包；不未经授权 fork／vendor 整个 GPUI。

**事实与候选**

- 微软 DWM 文档明确支持“自定义窗口框架保留标准最小化／最大化／关闭按钮”。候选是 HWND 上的 DWM 原生窗口框架接入，不是将三个通用 Button 当作原生 caption。
- 文档：<https://learn.microsoft.com/en-us/windows/win32/dwm/customframe>、<https://learn.microsoft.com/en-us/windows/win32/api/dwmapi/nf-dwmapi-dwmdefwindowproc>。已读取官方文档；包括 DwmExtendFrameIntoClientArea、自定义客户区与 DwmDefWindowProc 的非客户区优先处理／离开高亮清理要求。
- GPUI 自有非客户区处理和 DirectComposition 绘制与 DWM 的共存是未知项，不承诺官方 GDI 样例可以直接用于当前渲染管线。

**验证后再选择生产路线**

1. 原生 spike 在隔离窗口确认绘制和行为，保留一个整体顶栏；三键区域／DPI 从系统度量取得，不让 GPUI 图层遮住系统按钮，也不以固定 138px 猜所有系统尺寸。
2. 不替换整个窗口过程；若需小范围 subclass，明确安装／卸载和 HWND 生命周期，DWM 未处理消息继续 GPUI，窗口销毁后不留回调。不吞输入法、DPI、缩放、激活和关闭确认，不调用 DestroyWindow 绕过 dirty 文档保护。
3. Windows 原生 runner 上编译并运行相关无 UI 断言；真实 Windows 桌面检查原生绘制、关闭红色反馈、最大化后还原图案、拖动、边缘缩放、Win11 Snap、主窗和设置窗、100%／150%／200% DPI 与跨屏变化。构建 CI 不能替代以上桌面证据。
4. 若原生能稳妥工作，移除重复自绘三键，按系统按钮高度／占用区适配 Windows 顶栏，macOS／Linux 保持原政策。原生图案使用系统尺寸和 DPI，不强行缩放系统按钮。
5. 若原生有明确失败证据或需要已禁止的大规模框架改造，使用用户已同意的自绘替代：保留系统命中区域与 46px 基准按钮宽，将 10px 图案增至约 12–14px、统一最小化／最大化／还原／关闭视觉与关闭红色反馈，主窗和设置同时修正。替代仍须 Windows 行为验收，不冒称原生。
6. 仅缺少 Windows 运行环境／桌面证据不等于原生失败；记为待验证／BLOCKED，不借此自动启用替代并报告整项完成。

验收：原生路线或自绘替代路线附确切证据、失败原因和实机结果；只有原生系统绘制被核验才写“原生”。需要超出既定范围的依赖／GPUI 修改时回用户决策。
