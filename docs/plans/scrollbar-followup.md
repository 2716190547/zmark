# 滚动条问题排查与修复草案 v1

> 当前代理约定（2026-11-16）：herdr-triad 已弃用；由当前代理自行审查，不向其他 pane 派任务。本文跨窗格与独立代理审查要求仅作历史记录，现行规则见 [代理工作约定](../agent-workflow.md)。

## 已确认的使用场景

- 分屏时用鼠标滚轮滚动初始文档，可观察跳动；需确认触发方向、窗口尺寸并复现。
- 用户先前截图中的文档，拖动预览滚动条时指针与内容不跟手。
- 拖动离开窗口时，按指针垂直坐标继续控制，超出轨道的上下两端分别停在相应端点；松开立即结束。
- 保留虚拟列表和大文档资源预算；现有用户曾接受未测量区域的近似定位，但用户现要求改善跟手，须用实际文档检验。

## 事实与待验证假设

- `workspace.rs` 的根节点 `on_mouse_move` 只在 GPUI hitbox 悬停时触发；GPUI macOS 将拖动事件转换为包含窗口坐标的 `MouseMoveEvent`。窗口级 `Window::on_mouse_event` 和 `on_drag_move` 均值得评估；事件是否在窗口外持续投递、松开能否即刻收到，必须实测，不能由代码阅读保证。
- 滑块以 `(块索引 + 块内比例) / 块数` 表示，块高度差异大时并非像素比例；`at_end` 直接跳到 1，可能在边界造成突变。源文档跳动原因尚未证实。
- 分屏编辑器同步在目标块未测量时以零块高处理；行内换行进度直接加到块进度，可能在多行块内出现不连续。上述均为待复现实证的假设，不预设为根因。
- GPUI `ListState` 对未测项不提供完整文档高度；旧计划记录原生 scrollbar 最大偏移无法覆盖未测项。不能通过全量测量牺牲虚拟化来假称修复。

## 实施与验证关口

1. 先在隔离数据中使用初始示例文档建立分屏滚轮复现，分别记录编辑器偏移、预览 logical offset、滑块位置和末尾条件；分开判定内容回跳与滑块跳动。记录无法模拟的实际鼠标输入条件。
2. 使用截图同类且高度差异明显的文档验证拖动期间指针、滑块和可见内容的位置，区分滑块跟手和内容映射误差；不得读取或修改用户文档以外的状态作实验。
3. 依据证据修正根因；优先复用现有 GPUI 能力。保留滚轮、轨道点击、键盘、拖动、双向同步及已知首尾可达行为。拖动中外出、窗外松开、失焦、切换文档均须清理状态；窗口外事件能力需实机验证，若平台不投递则明确限制，不声称成功。
4. 新增针对真实缺陷可判别的回归，验证初始示例文档滚动末端、不同高度内容拖动和窗口外移动释放；运行相关历史测试、workspace 全量及项目规定专项。最终需实际鼠标检验，自动化受权限限制时明确报告，不将模拟等同真机验收。
5. 独立规划审查、问题答复及用户确认后方可改生产代码；修复后按项目流程交付，保留用户数据。

## v2：审查意见处理

- 窗口级监听仅能在 paint 阶段注册，监听器随帧重建，须只在一个事件分发阶段处理且不破坏已有命中与输入路由。`on_drag_move<T>` 需要同类型的 `cx.active_drag`；现有 `preview_scroll_drag` 不能触发它。使用任一方法前先验证拖放副作用和真实窗外事件，避免重复监听。
- 跟手验收：在轨道有效范围内按固定抓取点匀速拖动，稳定绘制后的滑块抓取点与鼠标纵坐标偏差不超过 2 pt；连续同向移动时不向反方向跳动（允许 2 pt 布局抖动），包括块高度变化与延迟测量前后。轨道两端和超出两端必须分别到达首尾，单个超过视口高度的末块也须完整可达。分屏中鼠标滚轮连续同向滚动时分别记录内容与滑块，不出现反向突跳或底端来回闪动。记录输入和绘制后坐标的采样方法。用户此前接受未测块按文档顺序估算，内容相对物理高度可以非线性，但滑块应跟住鼠标。
- 若实际平台不能持续传递窗外事件或松开事件，先向用户说明证据和可选替代方案并取得决定；不得静默降级并宣称完成。

## v3：补充隔离和性能验证

- 将用户授权的目标文档及相邻资源只读复制到临时目录，使用私有配置和副本工作区，禁写原件；比对原件 hash 与 mtime。其余实验使用仓库示例和自造数据，不记录正文。前文“不得读取或修改用户文档以外的状态作实验”以本条替代。
- 以短文、块高不均文档、长文和单一超长块分别比较同条件修改前后：记录事件数、实际测量项数、绘制时间或交互延迟与 physical footprint；检查虚拟化未退化成全量测量，避免每事件额外遍历全文。若有明显回归先修复；不能解决时报告具体证据与限制。
