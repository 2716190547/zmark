# ZMark 0.2.16 规划

2026-11-27 制定。来源：GitHub issue #30（预览模式下编辑、多标签）。

## 已定决策

- 预览内编辑做「按块就地编辑」，不做 Typora 式完整所见即所得。
- 多标签做成可选标签条。
- 两项功能各有一个设置开关，默认都关闭。关闭时行为与 0.2.15 一致，ADR 0031 的无标签头部仍是默认。
- 全部放进 0.2.16。

## 现状

- 多文档状态已存在：`AppState.open_docs: Vec<OpenDoc>`、`active: Option<DocKey>`，脏关闭和退出保护已在 ADR 0031 落地。
- 全局只有一个 `EditorEngine`。`switch_document` 调用 `reset_text`，会清空撤销/重做栈，并且光标只是被截断到合法范围（`editor_engine.rs:247`）。切走再切回就无法撤销。
- 每个顶层块有 `SourceAnchor { block_index, source_line_start, source_line_end }`。`EditorEngine::replace_source_range` 已提供可撤销的回写，图片路径修复在用（`workspace.rs:5329`）。

## 范围

### 批次 0：用户反馈的缺陷（2026-11-27）

先修这一批，再开始功能开发。

2026-11-27 实施状态：第 1、2、3、5、6、7 项及第 4 项的「连续点击同一文件」已改，安装到本机待验收。第 4 项「不同文档之间切换」的闪动留待批次 1 与编辑会话一起处理。第 2 项的 Windows 实现本机无法编译，需 CI 编译并在 Windows 上手动验证。第 5 项只改了显式设置行高的段落、列表项和代码块；标题和表格单元格本来就没有设置行高（使用 GPUI 默认值），保持不变。

1. **别针图标点击无法取消置顶**。`drawer.rs` 的 `pin_badge` 只是一个 `svg()`，没有点击处理，点击会落到所在行上，效果是打开文件或展开文件夹。取消置顶目前只能走右键菜单。修复：让别针图标可点击，调用 `on_toggle_pin`，并 `stop_propagation`，悬停提示显示「取消置顶」。根目录行、文件夹行、文件行、外部文件行四处都用了这个徽标，要一起改。
2. **Windows 右键「在 Finder 中显示」没有反应**。GPUI 的 Windows 端 `reveal_path` 在后台线程调用 `SHGetDesktopFolder` 和 `SHOpenFolderAndSelectItems`，但只有主线程执行过 `OleInitialize`，后台线程没有初始化 COM，调用失败后只写日志（`gpui-pre-windows-0.3.12/src/platform.rs:816`、`:1543`）。修复：Windows 上不走 `cx.reveal_path`，改为在后台线程启动 `explorer.exe /select,"<路径>"`，并去掉 `canonicalize` 可能带上的 `\\?\` 前缀。本机没有 Windows 目标，要靠 CI 编译，并在 Windows 机器上手动验证。
3. **菜单文案「Finder」改为「文件夹」**。`i18n.rs` 的 `reveal_in_finder` 共 11 种语言。按用户决定，所有平台统一为「在文件夹中显示」及各语言的对应说法，macOS 也一样。字段改名为 `reveal_in_folder`。
4. **在多个文档之间切换时预览频闪**。`on_document_swapped` 调用 `reset_preview_list`，导致：
   - 虚拟列表把所有块高度重置为 `DEFAULT_ITEM_HEIGHT`，滚动位置归零。第一帧按估算高度排版，测量完再重排。
   - 清空 `syntax_cache`，代码块先以纯文本显示，异步着色完成后再变色。
   - `release_hidden_diagrams` 释放图表纹理，切回来后 Mermaid 要重新栅格化。

   - **已定位（连续点击同一文件）**：侧栏文件行的点击处理（`workspace.rs` 中 `DocKey::Path` 分支）调用 `load_file` → `open_file`。对当前文档，`switch_document` 会提前返回，但随后的 `on_document_swapped` 照常执行，滚动、块高度、着色和图表都被重置，所以每点一次预览就重排一次。修复：目标已经是当前文档时，跳过 `load_file` 和 `on_document_swapped`，只保留选中和展开。`on_select_doc` 回调也做同样的判断。
   - **在不同文档之间切换**：上面列的重置仍会造成一次闪动。修复方向：每个文档保留测量好的块高度和滚动位置（与批次 1 的编辑会话合并），按文档保留语法着色缓存，切换时不清空。先用帧探针增加一个 `doc-switch` 场景测量，再决定做到什么程度。
5. **行高设置不影响预览正文**。`preferences.line_height`（设置里的「行高比率」，范围 1.3–1.7，默认 1.6）只被源码编辑器读取（`workspace.rs:879`、`:1141`）。预览的正文、列表、引用、表格都把行高写死为 1.75，代码块写死为 1.6（`preview.rs:589` 等）。修复：预览正文改为读取这个偏好。`TextRegionInfo.line_height_factor` 必须和渲染用同一个值，否则选区和命中测试会错位。修改行高后要让虚拟列表的块高度失效并重新测量。
   - 已定（用户确认）：预览行高 = 偏好值 + 0.15。默认 1.6 对应预览 1.75，与现在一致；代码块按同样的差值跟随（默认 1.6 不变则为偏好值）。
6. **大纲文字偏小**。侧栏大纲行用的是 `text_xs()`（12px），文件树行是 13px，所以大纲看起来更小。预览里的 `[toc]` 目录卡片也是 `text_xs()`。修复：大纲行改为 13px，与文件树一致，并按层级调整行距和缩进；目录卡片跟随正文字号缩小一档，不再固定 12px。改完后在浅色和深色主题下各截图核对一次。（用户已确认两处都改。）
7. **预览里的任务复选框看起来可点，实际点不了**。欢迎页「列表与交互任务清单」中的 `- [ ]` / `- [x]` 在预览里渲染成复选框（`preview.rs:1608`），但没有点击处理。已定（用户确认）：做成可点击勾选。用 `ListItem` 的源码位置找到 `[ ]` / `[x]`，经 `replace_source_range` 写回，这样可以撤销，也会标记为未保存。

8. **勾选复选框或连续调整行高后频闪、出现空行**。每次重新解析或行高变化，虚拟列表会丢弃所有已测量的块高度，所有块退回估算高度，等下一帧测量后再重排。修复：重新解析时，按内容相同的公共前缀和公共后缀保留旧的测量高度，只有改动的块重新测量。
9. **置顶别针在文件夹行偏左**。别针排在隐藏的「−」「+」按钮之前，这两个按钮透明但仍占位置。改为排在最后。
10. **右键文件夹可新建文件、新建文件夹**。新建文件夹沿用「未命名文件夹」「未命名文件夹 1」……的命名，建好后直接进入改名。
11. **头部按钮右侧与上下的间距不一致；状态胶囊改为圆角矩形**。macOS 头部右侧内边距从 12px 改为 5px，与按钮上下各 5px 一致。右下角的状态和语法提示改为 6px 圆角，与头部按钮相同，距右边和底边都是 12px。

### 批次 1：预览同帧测量，消除频闪（2026-11-27 用户确认先做）

根因：`PreviewScrollState` 先按高度表（未测量的块用估算值）定位块，绘制时才拿到真实高度，下一帧再修正。用估算值排版的那一帧会显示出来，表现为空行和跳动。重新解析、调整行高、切换文档、窗口改宽都会触发。

1. 可见块改为在同一帧内测量后再定位，参照 GPUI `list()` 在 prepaint 中调用 `layout_as_root` 的做法（`gpui-pre-0.3.12/src/elements/list.rs`）。屏幕外的块继续用高度表里的估算值驱动滚动条，保留 `virtual_list.rs` 开头记录的、不用 `ListState` 的理由。
2. 测量后以视口顶部的块为锚点保持像素位置，沿用 `top_anchor`。滚动条拖动和贴底的规则保持不变。
3. 划词选区、命中测试和自动滚动依赖块的位置（ADR 0037），要在新的定位方式下保持一致。
4. 图片和 Mermaid 按已知或缓存的尺寸预留高度，加载完成后不再撑开。
5. 和下面的「每个文档独立的编辑会话」合并：每个文档保存自己的高度表、滚动位置和语法着色缓存，切换时不再重置。
6. 验证：帧探针新增 `doc-switch`、`task-toggle`、`line-height` 场景，并对比 `drag-scroll`、`resize` 改造前后的数据。本批完成后串行重跑 Phase H/I 专项。按项目约定，这些测试在提交门禁时运行，迭代过程中只编译和安装。
7. 新增 ADR，记录预览从「下一帧修正」改为「同帧测量」，并说明与 ADR 0026、0037 的关系。

2026-11-27 实施状态：
- 第 1～3 项已实现：新增 `views/preview/measured_blocks.rs`，可见块在 prepaint 中 `layout_as_root` 后按真实高度从首块的表内位置向下排列，再上报给高度表；高度表以视口顶部块为锚点同步。块不再用 `absolute` 和 `min_h` 估算高度。划词和命中测试的区域仍在同一帧内按实际位置登记。
- 第 5 项已实现：撤销/重做、光标和选区随 `OpenDoc` 保存（后台文档合计上限 32 MiB，超出时先清最大的历史）；预览高度表和滚动位置按文档保存，按缓冲区哈希校验，内容变了就不复用；语法着色缓存按代码内容索引，切换文档时不再清空。
- 第 4 项已实现（2026-11-28）：图片按文档和 URL 记住解码过的尺寸，重新解码时占位块与最终尺寸一致；Mermaid 记住 SVG 尺寸，重新解析时按该尺寸显示空卡片。首次加载仍无法提前得知尺寸，加载完成时下方内容会移动一次。

### 批次 1b：每个文档独立的编辑会话

1. `OpenDoc` 保存自己的撤销/重做栈、光标、选区和滚动位置。切换时把当前 `EditorEngine` 的会话状态存回去，再载入目标文档的状态，不再调用 `reset_text` 清空历史。撤销字节预算改为所有文档合计，超出时从最久未使用的文档开始丢弃历史。
2. 外部修改重载、重命名、另存为后升格 `DocKey` 等路径，确认会话状态跟着迁移或按需清空。

这是多标签的前置条件，也是独立的缺陷修复，开关关闭时同样生效。

### 批次 2：可选标签条

3. 在 `Preferences` 里新增 `show_tab_bar: bool`，默认 `false`，放在设置的「编辑器」分组。
4. 开启后，在头部显示从 `open_docs` 派生的标签条，不新增状态。每个标签显示文件名、脏点和悬停时出现的 ×。当前标签兼任标题，双击改名；标签条两侧的空白处保留 `start_window_move()`。标签过多时横向滚动，不压缩到看不清。
5. 快捷键 `Ctrl+Tab` / `Ctrl+Shift+Tab` 切换，`Cmd+1…9` 跳转。快捷键在开关关闭时也可用，用来在已打开文档之间切换。`Cmd+W` 沿用现有的关闭流程和脏检查。
6. 标签可以拖动排序，顺序写回 `open_docs`。会话恢复保留这个顺序。
7. 新增 ADR，记录对 ADR 0031 第 1 节的修订：默认无标签，可选标签条。先按 ADR 0029 核对 GPUI 0.2 窗口装饰和拖拽区的限制。

### 批次 3：预览按块编辑

8. 在 `Preferences` 里新增 `preview_inline_edit: bool`，默认 `false`。
9. 开启后，在预览模式和分屏的预览侧，单击块进入编辑。该块就地替换为一个编辑框，内容是 `source_line_start..=source_line_end` 的源码行。编辑框复用源码编辑器的渲染和语法着色，其他块保持渲染。
10. 编辑框直接修改共享的 `EditorEngine`，所以撤销、脏状态、自动保存和分屏源码侧都会同步。按 Esc、点击其他位置或光标移出块边界时退出，然后触发增量重新解析。
11. 交互冲突：拖动仍是预览划词。只有不带拖动的单击才进入编辑，链接、图片、复选框、代码块复制按钮保持原有行为。
12. 分步覆盖块类型：
    - 第一步：段落、标题、分隔线。
    - 第二步：列表和引用，编辑范围取最外层块，避免嵌套边界算错。
    - 第三步：表格，整表作为一个块。
    - 代码块和 Mermaid 不支持就地编辑，单击仍走现有行为，双击跳到源码。
13. 虚拟列表：编辑框高度变化时，用块索引和块内偏移保持滚动锚点，内容不跳动。按 ADR 0026 和 0037 核对大文档分层解析与选区的约束。
14. 中文输入法：编辑框必须走现有编辑器的 IME 通路，在组字期间不提交、不重新解析。

## 风险

- 批次 3 改动最大。最可能出问题的地方是块边界与源码行的映射（列表、引用、紧邻的块）、编辑时重新解析造成的块索引漂移，以及 IME。开关默认关闭，可以把风险挡在主路径之外。
- 批次 1 改变了撤销内存的上限模型，需要在多文档和大文档下核对内存。

## 执行方式

- 在 `dev` 分支按批次提交。日常迭代用 `./scripts/bundle_macos.sh --install` 安装到本机验收，过程中不运行测试。
- 每个批次在 `GLOSSARY.md` 补充术语：编辑会话、标签条、块编辑。
- 发版前在最终候选上运行 `scripts/full_gate.sh --bundle`，同步更新 README、README.zh-CN、`docs/releases/v0.2.16.md`，在欢迎页清单里加入两个开关的说明，并回复 issue #30。
