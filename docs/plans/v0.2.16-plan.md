# ZMark 0.2.16 规划

2026-11-27 制定。来源：GitHub issue #30（预览模式下编辑、多标签）。

## 已定决策

- 预览内编辑做「按块就地编辑」，不做 Typora 式完整所见即所得。
- 多标签做成可选标签条。
- 两项功能各有一个设置开关，默认都关闭。关闭时行为与 0.2.15 一致，ADR 0031 的无标签头部仍是默认。
- 全部放进 0.2.16。

## 现状

- 多文档状态已存在：`AppState.open_docs: Vec<OpenDoc>`、`active: Option<DocKey>`，脏关闭和退出保护已在 ADR 0031 落地。
- 全局只有一个 `EditorEngine`。`switch_document` 调用 `reset_text`，会清空撤销/重做栈，并且光标只是被截断到合法范围（`editor_engine.rs:247`）。切走再切回就无法撤销。
- 每个顶层块有 `SourceAnchor { block_index, source_line_start, source_line_end }`。`EditorEngine::replace_source_range` 已提供可撤销的回写，图片路径修复在用（`workspace.rs:5329`）。

#### 预览同帧测量（消除空行和跳动）

- 根因：旧做法先按估算高度定位块，下一帧才按真实高度修正，用估算值排版的那一帧会显示出来。重新解析、调整行高、切换文档、改窗口宽度都会触发。
- 新增 `views/preview/measured_blocks.rs`：可见块在 prepaint 中先 `layout_as_root` 测得真实高度，再从首块的表内位置向下排列并绘制，同一帧完成。屏幕外的块仍用高度表估算值驱动滚动条（`f8f5233`）。
- 重新解析后按公共前缀和后缀沿用未变块的真实高度（`2b700c0`）。
- 图片按文档和 URL、Mermaid 按源码哈希记住尺寸，再次加载时按最终尺寸占位；首次加载仍会在完成时撑开一次（`7f29f30`）。
- 决策记录：ADR 0039；术语：`GLOSSARY.md`「编辑会话」「同帧测量」。

#### 每个文档独立的编辑会话与预览状态

- 撤销/重做、光标、选区存放在 `OpenDoc.session`，切换文档后保留；后台文档历史合计上限 32 MiB，超出先清最大的一份。后台文档从磁盘重新加载时清空其历史，与当前文档一致（本次整理提交）。改名和另存为时会话随 `OpenDoc` 一起迁移（`f8f5233`）。
- 预览高度和滚动位置按文档保存，按缓冲区哈希校验，内容变了不复用；语法着色缓存切换文档时不再清空（`f8f5233`）。

#### 同帧测量引入并已修复的回归

- 本地图片（SVG、PNG 等）一直停在灰色占位：块改在 prepaint 构建后，解码结果在 `begin_frame` 清空登记之后才核对，每次都被当作不需要而丢弃。改为先核对再清空（`dc7638f`）。凡在 `render` 内假设预览块已构建的逻辑都可能受同类影响，已核对 Mermaid 的帧计数（有一帧余量，不受影响）。

#### 帧探针测量

release 构建，120Hz 屏，窗口在前台；屏幕锁定时 macOS 不出帧，探针拿不到数据。新增场景 `doc-switch`、`task-toggle`、`line-height`（从第 500 块开始，结束时打印顶部块和当前文档）、`bottom-scroll`；`ZMARK_FRAME_PROBE_MODE=split` 可在分屏下运行任一场景。

| 场景 | p50 | p95 | >16.7ms 帧数 / 总帧数 | 结束时顶部块 |
| --- | --- | --- | --- | --- |
| `drag-scroll` | 8.33ms | 9.3–12.3ms | 3–8 / 339–355 | — |
| `table-select` | 8.33ms | 8.37–8.91ms | 0–3 / 354–361 | — |
| `resize` | 9.26–9.39ms | 21.4–22.5ms | 38–49 / 275–283 | — |
| `doc-switch` | 8.33ms | 11.2–16.1ms | 6–12 / 334–343 | 500（文档 b） |
| `task-toggle`（立即解析前） | 8.33ms | 11.0–11.1ms | 4–6 / 345–348 | 500 |
| `task-toggle`（立即解析后） | 8.34ms | 16.4–16.5ms | 11–14 / 330–338 | 500 |
| `line-height` | 8.34ms | 13.1–13.8ms | 8–10 / 337–341 | 500 |
| `bottom-scroll`（预览 / 分屏） | 8.33ms | 13.5 / 10.0ms | 7 / 4，约 340 | 23 |

与 0.2.15 基线相比，`drag-scroll`、`table-select` 持平，`resize` 的 p50 从 13.9–14.9ms 降到约 9.3ms。帧时间不能证明没有空行，需人工目视验收。

- 已知限制：光标映射对 HTML 实体、转义和自动编号可能偏几个字符；框内拖选不自动滚动；框内不支持中键列选；编辑框不保留渲染样式。

原计划：


8. 在 `Preferences` 里新增 `preview_inline_edit: bool`，默认 `false`。
9. 开启后，在预览模式和分屏的预览侧，单击块进入编辑。该块就地替换为一个编辑框，内容是 `source_line_start..=source_line_end` 的源码行。编辑框复用源码编辑器的渲染和语法着色，其他块保持渲染。
10. 编辑框直接修改共享的 `EditorEngine`，所以撤销、脏状态、自动保存和分屏源码侧都会同步。按 Esc、点击其他位置或光标移出块边界时退出，然后触发增量重新解析。
11. 交互冲突：拖动仍是预览划词。只有不带拖动的单击才进入编辑，链接、图片、复选框、代码块复制按钮保持原有行为。
12. 分步覆盖块类型：
    - 第一步：段落、标题、分隔线。
    - 第二步：列表和引用，编辑范围取最外层块，避免嵌套边界算错。
    - 第三步：表格，整表作为一个块。
    - 代码块和 Mermaid 不支持就地编辑，单击仍走现有行为，双击跳到源码。
13. 虚拟列表：编辑框高度变化时，用块索引和块内偏移保持滚动锚点，内容不跳动。按 ADR 0026 和 0037 核对大文档分层解析与选区的约束。
14. 中文输入法：编辑框必须走现有编辑器的 IME 通路，在组字期间不提交、不重新解析。

## 风险

- 批次 3 改动最大。最可能出问题的地方是块边界与源码行的映射（列表、引用、紧邻的块）、编辑时重新解析造成的块索引漂移，以及 IME。开关默认关闭，可以把风险挡在主路径之外。
- 批次 1 改变了撤销内存的上限模型（后台合计 32 MiB），需要在多文档和大文档下核对内存。
- 批次 1 把预览块的构建移到 prepaint，`render` 里依赖块已构建的逻辑可能出现与本地图片同类的回归。
