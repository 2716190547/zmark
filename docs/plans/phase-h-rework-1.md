## 六项阻断问题与验收要求

### R1：接通字符级正文选区（H2）

审查发现 `preview_selection` 从未被赋值，只有块级范围，无拖选处理，Cmd+C 分支不可触发。

必须支持段落中间起止、同段部分选取、双向拖选、跨段落及不可见块、表格局部范围、边缘自动滚动和鼠标松开结束选取。按实际文字范围高亮及复制，不能替代为整块背景及整块复制。状态须在文档切换或重新解析后安全失效；剪贴板快捷键按焦点路由。

保留虚拟化及原规划的纯文本规则。复用已实现的序列化能力，但增加针对生产事件链路、字符范围和剪贴板内容的验证；只测序列化不代表选取交互完成。

### R2：统一真实文字布局（H0）

审查发现点击与光标只 shape 纯文本，折行仍使用 `char_unit_width` 猜测；行内代码左右各 4px 内边距没有进入命中与光标几何。

审查复现：14px 下 `abc code def` 含一个行内代码片段，实际几何位置约 83.6px、函数约 75.6px，恒漂移 8px；测试环境中 Tab 的实际 advance 为 8.4px，折行估算为 33.6px。这些数值是测试环境证据，不作为跨字体固定常量。

生产绘制、折行、光标与命中必须共享实际排版依据，涵盖样式内边距及 Tab 的实际呈现。验证中英混排、多个行内样式、软折行、Source/Split、字号、侧栏及窗口宽度变化；不得仅调宽度系数，也不得以同一纯文本 shaping 结果互推的镜像测试证明实际渲染一致。

### R3：实现中文输入法及基本输入编辑（H1）

当前 `on_key_down` 拼字符不能承接系统 IME 组合输入，全仓无输入处理器链路。

使用 GPUI 公开输入处理接口实现搜索的组合输入、候选确认/取消、粘贴、删除、光标移动与选区替换；输入框独立焦点，输入与剪贴板操作不得泄漏到源码。参考现有 GPUI 官方 input 示例，不另加庞大输入框架。

### R4：搜索框固定顶部（H1）

当前搜索框位于 `drawer_content_scroll` 的 `overflow_y_scroll` 内。必须将其放在文件页固定区域，目录列表独立滚动，保留草稿入口；长列表滚动后仍能操作搜索。

### R5：真正后台搜索与异步状态（H1）

当前按键路径 `set_search_query → expand_ancestors_for_matching_files → scan_root_layer → fs::read_dir` 在 UI 线程同步运行，`search_in_progress` 从未置真。

将遍历放到后台，保留扫描预算及未展开目录覆盖；查询变化、清空、根目录移除后不得应用旧结果。扫描中、无结果、不完整提示必须由实际状态驱动。`search_in_progress` 是需求需要的状态，应接通其生命周期，不得仅删除字段来消除死代码。

原展开状态的保存不得依赖会因删除而串位的根索引。验证多根目录删除、搜索期间移除根、清空恢复以及慢扫描期间继续输入。

### R6：移除搜索 Emoji

`drawer.rs` 的搜索符号违反现有零 Emoji 规范。使用项目风格一致的 SVG 图标；必要时恢复 `search.svg`，不增加图标依赖。
