# ADR 0040：可选标签条

状态：Accepted，2026-11-28。来源：GitHub issue #30。修订 ADR 0031 第 1 节。

## 背景

ADR 0031 去掉了右侧头部的 Tab Strip，文档切换收敛到侧栏。issue #30 要求恢复多标签。多文档状态（`open_docs`、`DocKey`、脏关闭保护）一直保留，按文档的编辑会话在 ADR 0039 落地，所以标签条只需要一层显示和交互。

## 决策

1. **默认仍无标签**。`Preferences.show_tab_bar` 默认 `false`，关闭时头部与 0.2.15 一致。开关在设置「编辑器与保存」分组。
2. **标签从 `open_docs` 派生**，不新增文档状态。每个标签显示文件名，脏点和悬停时的 × 共用一个 16px 槽位，悬停不改变标签宽度。当前标签兼任标题：双击在标签内改名，悬停显示完整路径。中键点击关闭。
3. **关闭沿用现有流程**。× 和中键都调用 `trigger_close_doc`，后台脏文档先切到前台再询问保存，与侧栏 × 和 `Cmd+W` 相同。
4. **拖动排序写回 `open_docs`**。退出时 `remember_session` 按 `open_docs` 顺序保存，下次启动按同一顺序重开，因此不需要额外字段。
5. **溢出横向滚动**。标签不压缩，最大宽 220px；标签条用 `overflow_x_scroll`，竖向滚轮也会转为横向滚动（GPUI 在只有横向可滚时这样处理）。切换文档后用 `ScrollHandle::scroll_to_item` 让当前标签保持可见。
6. **拖拽区**。按 ADR 0029，窗口拖动只绑定在标签条与右侧工具之间的 `canvas_header_drag_area`，标签本身不参与窗口拖动，标签的 `on_drag` 只用于排序。开启标签条后头部左内边距改为画布边缘的固定值，不再对齐正文列，以容纳更多标签。
7. **快捷键固定，开关关闭时也可用**。
   - `Ctrl+Tab` / `Ctrl+Shift+Tab`：按标签顺序切到下一个 / 上一个文档，首尾循环。
   - 按位置跳转：macOS 为 `Ctrl+1…9`，Windows/Linux 为 `Alt+1…9`；`9` 总是最后一个文档。`Cmd+1…3`（Windows/Linux 为 `Ctrl+1…3`）已用于切换视图模式，所以不用 `Cmd+数字`。
   - 这些键不进入可自定义快捷键列表。源码编辑器的 Tab 缩进不再响应带 Ctrl 或 Alt 的 Tab。

## 结果

- 喜欢侧栏导航的用户不受影响；需要标签的用户打开开关即可。
- 标签条没有自己的状态，不会与侧栏的 active/open/dirty 显示出现不一致。
- 已知限制：标签条两侧没有滚动箭头，也不显示溢出提示；拖动排序只能在标签之间放下，放在空白处不生效。
