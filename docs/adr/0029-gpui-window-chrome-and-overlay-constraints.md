# ADR 0029: GPUI 0.2 窗口装饰与图层变换约束

## 状态
已接受 (Accepted)

## 上下文 (Context)
在落地 ADR 0027 的双板块画布、红绿灯折叠避让与矢量灯箱时，对 GPUI 0.2.2 的实际能力做了验证，确认三条与设计稿心智模型不同的约束：

1. **红绿灯只有创建时位置**：`WindowOptions.traffic_light_position` 在窗口创建时读取，GPUI 0.2 未暴露运行时调整 `NSWindow` 红绿灯位置的 API。
2. **没有 CSS transform**：GPUI 的 `div` 样式不支持 `transform: matrix()`，不能按 Web 方式做合成层缩放/平移。
3. **窗口拖拽需要显式绑定**：透明标题栏下，空白区域必须通过 `on_mouse_down` 调用 `Window::start_window_move()`，否则用户无法拖动窗口。

## 决策 (Decision)

1. **红绿灯采用静态位置 + 动态安全区**：固定初始化在窗口左上 `(14, 12)`；侧栏展开时它自然位于导航头部；侧栏折叠到 0px 时，右侧画布头部注入 `76px` 左安全区并显示“展开侧栏”，不宣称红绿灯发生了运行时迁移。
2. **拖拽区显式声明**：左侧导航头部空白、右侧标签栏与工具区之间的空白均绑定 `start_window_move()`。
3. **灯箱用布局属性而非变换矩阵**：缩放通过调整 SVG 图片尺寸实现，平移通过容器的 `relative().left()/top()` 实现；不引入自制的 transform 抽象。
4. **先验证再实现**：后续涉及窗口装饰、合成层、手势的 UI 需求，先确认 GPUI 0.2 的 API 存在，再决定实现或记录限制。

## 结果 (Consequences)

- 跨平台行为可预测，不依赖未公开的 AppKit 私有调用。
- macOS 侧栏折叠态与设计稿存在“红绿灯静态位置”的视觉差异，已作为已知限制记录；折叠时通过 76px 安全区保证不遮挡。
- 灯箱保持矢量清晰度与流畅缩放，但缩放/平移属于布局计算，不是 GPU 合成层变换；超大图表下需关注布局开销。
- 这些约束已沉淀到仓库根 `AGENTS.md`，执行代理无需每次由协调者重复提醒。
