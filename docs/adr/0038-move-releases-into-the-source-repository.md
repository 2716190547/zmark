# ADR 0038：发行资产迁回源码仓库，并通过过渡版归档 zmark-releases

状态：Accepted，2026-11-24，用户确认。

源码仓库 `2716190547/zmark` 公开后，再单独维护发行仓库只会增加一处需要同步的地方。从 0.2.13 起，安装包、签名更新清单和发布说明都发布到 `2716190547/zmark/releases`。`zmark-releases` 不删除也不设为私有，改为归档，以保留历史下载和旧更新源。

## 决策与取舍

- 0.2.12 及更早的客户端只认 `zmark-releases` 的 `latest.json`，并只接受指向该仓库的安装包地址。因此 0.2.13 作为过渡版发布两次：发到 `zmark-releases` 的清单仍指向旧仓库，供旧客户端升级；发到 `zmark` 的清单指向新仓库。两份清单分别签名，安装包是同一次 CI 产物。旧仓库收到 0.2.13 后才归档。
- 0.2.13 起，客户端只信任 `zmark/releases` 的地址。Gitee 上的 0.2.13 保留旧格式清单，供旧客户端在国内备用链路下升级。新客户端已是 0.2.13，不会再下载这一版，所以不需要兼容旧地址的代码。
- Gitee 镜像仓库 `zeng_sc/zmark-releases` 保留原名，因为已安装的客户端写死了它的地址。同步工作流迁到源码仓库，使用其中的 `GITEE_RELEASE_TOKEN` Secret。
- 历史 Release 不迁移。在源码仓库为旧版本补建标签和资产，需要逐个核对发布源提交，收益很小。

## 后果

- 归档后，没有升级到 0.2.13 的旧客户端不再收到更新提示，只能手动下载新版本。
- 在源码仓库创建 Release 会生成 `v<version>` 标签。`scripts/release.sh` 会把标签固定到已推送的构建提交。
