# ADR 0025: 沉浸式阅读排版、轻量纯 Rust 代码着色与无界呼吸感画布重构

## 状态
已接受 (Accepted)

## 上下文 (Context)
在对 GlideMark 原生界面的深度审视与代码排查中，发现了若干破坏沉浸式阅读体验、排版不协调以及 Markdown 解析缺陷的关键问题：
1. **副顶栏视觉冗余破坏呼吸感**：
   - 预览区（Preview）与源码区（Editor）顶部常驻 32px 的次级信息栏（分别展示「预览 / 12 blocks」与「源码 / 行列信息」）。
   - 顶栏中心的分段选择器已清晰标明当前视图模式；「12 blocks」为开发内部 AST 计数，对真实阅读和写作带来不必要的视线干扰，且白白挤占了垂直空间。
2. **Markdown 列表行内富文本与嵌套结构丢失 Bug**：
   - 在 `glidemark_core::ast::collect_list_items` 中存在手写的简化解析循环，丢弃了除纯文本与行内代码以外的所有事件。导致列表项中的粗体（如 `**Blazing Fast**`）、斜体、链接等富文本全部降级为平淡无样式的常规字符。
   - 嵌套列表（子列表）被错误拍平在同一层级，且缺少层级间缩进。列表符号使用生硬的破折号 `–`（en-dash），缺少现代排版美感。
3. **代码块缺乏语法高亮与复制失效**：
   - 代码块虽然渲染了语言标牌（如 `RUST`）与行号，但正文代码完全为单一黑白单色，未作词法着色。
   - 代码块右上角的复制按钮仅配置了 Tooltip，未挂载剪贴板点击事件（`on_click`），用户点击无任何反应。
   - 代码块内容容器缺少横向平滑滚动（`overflow_x_scroll`），长行代码存在溢出或断裂隐患。
4. **阅读版心缺乏居中限制与底部裁切**：
   - 预览容器忽略了用户的 `max_column_width` 配置，在宽屏窗口下单侧靠左对齐，右侧产生巨大空洞；且底部缺乏回弹内边距，最后一行内容贴合窗口底边被截断。
5. **侧边栏默认 Tab 与空状态生硬**：
   - 打开单文档或新建空白文档时，侧边栏固定默认选中「文件 (Files)」Tab 并展示空洞的「无 Markdown 文件」，而该文档自身的标题大纲（Outline）本可提供即时导航价值。

## 决策 (Decision)
1. **彻底移除双栏 32px 副顶栏 (Borderless Reading Canvas)**：
   - 预览区与源码区全面消除 32px 次级顶栏与分割线，还原 MiaoYan 式纯白呼吸感；
   - 源码区光标行列信息下沉为底部极简微胶囊，保持编辑与阅读双侧界面的对称纯粹。
2. **AST 列表引擎重构 (Nested Lists & Inline Styles)**：
   - 重写 `collect_list_items`，全面支持递归嵌套列表；
   - 修复列表内行内样式解析，完整还原粗体、斜体、删除线、行内代码与链接；
   - 列表符号升级：一级列表采用现代实心圆点 `•`，二级及以下采用空心圆点 `◦`。
3. **纯 Rust 主题自适应轻量词法着色器 (Pure-Rust Syntax Highlighter)**：
   - 实现轻量、零外部重型依赖的词法分析器，支持主流语言（Rust, JS/TS, Python, Shell, JSON, HTML 等）核心词法着色（关键字、字符串、注释、数字、类型等）；
   - 色彩直接绑定 GlideMark 8 套主题调色板，支持深浅模式无感切换；
   - 为代码复制按钮挂载 GPUI 原生剪贴板复制事件（`cx.write_to_clipboard`），并补充代码横向滚动支持。
4. **居中舒适版心与安全底边距**：
   - 预览容器基于 `preferences.max_column_width` 实施 `max_w` 与居中排列（`mx_auto`）；
   - 为滚动容器增加 `pb_24` 安全下边距，保证在滚动至文末时文字始终留有充足视觉余量。
5. **侧边栏智能 Tab 与操作引导**：
   - 无工作区目录且当前文档包含 H1~H6 时，侧边栏智能默认聚焦「大纲 (Outline)」Tab；
   - 文件列表为空时，提供「打开文件夹...」的优雅微胶囊快捷操作。

## 结果 (Consequences)
- **正面收益**：
  - 阅读与写作界面彻底消除多层线条阻隔，真正呈现出如同纸张般的极简呼吸感；
  - 完美修复 Markdown 列表内无法加粗和嵌套子列表的核心 AST Bug；
  - 代码块拥有优雅的自适应主题色彩与真正可用的复制体验；
  - 宽屏与长文档下的阅读排版更加符合人眼工程学，杜绝窗口底边截断文字。
- **架构保证**：
  - 不引入额外的外部重型二进制依赖包（如全量 syntect/tree-sitter），保持超低启动开销与极小内存占用（<50MB）。
