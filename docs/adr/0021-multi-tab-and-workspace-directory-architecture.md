# ADR 0021: 单窗口轻量多标签页 (Multi-Tab) 与工作区目录树架构

## 状态
已接受 (Accepted)

## 上下文 (Context)
1. **多开文件与文件夹诉求**：
   - 此前 GlideMark 采用单活动文档模型，打开新 Markdown 文件会直接替换当前正在查看或编辑的文件，无法在多个相关文档（如主文档、大纲、数据字典、附录）之间保留上下文与快速来回切换。
   - 用户提出多开需求，并要求评估单窗口与多窗口的系统资源消耗差异与交互规划。
2. **资源消耗与架构权衡 (Resource & Architecture Trade-off)**：
   - **多窗口模式 (Multi-Window)**：在 GPUI / macOS 架构下，每个独立窗口都需要向操作系统请求一个原生 `NSWindow` 并分配专用的 Metal Surface 离屏上下文与 DisplayLink 垂直同步回调。单窗口基础开销约为 15~25MB。若用户打开 10 个 Markdown 文件产生 10 个独立窗口，额外内存消耗约 150~250MB，且桌面窗口重叠零散。
   - **单窗口多标签页模式 (Single-Window Multi-Tab)**：仅维持单套 GPU Metal Surface。在 Rust 内存模型下，一个纯文本 Markdown Document（包含 Buffer、行索引、语法 AST 与锚点映射）的内存储备仅约 50KB ~ 500KB。即使同时常驻打开 50 个文档标签页，增量内存占用亦低于 5MB，总内存平稳维持在 40~50MB 之间。切换标签页零延迟、零重排、零 GPU 额外负载。
   - **综合决策**：默认采用**单窗口多标签页**作为第一主交互，保留 `⌘W` 关闭标签与 `+` 新建标签；同时保留独立新窗口机制（通过系统快捷键独立启动）以兼顾多屏对照场景。
3. **工作区文件夹 (Workspace Folder) 规划**：
   - 在侧边栏顶部工具栏集成「打开文件夹」快速入口（`icons/folder.svg`）。
   - 用户点击后调用系统原生文件夹选择器，选定后自动递归扫描该工作区目录下的所有 `.md` / `.markdown` 文件并扁平化/层级化注入抽屉文件列表，解决项目级文档组织问题。
4. **侧边栏视觉与层级优化**：
   - 顶部切换器改造为纯图标模式（Icon-only），文字移入 Hover Tooltip，整体靠左紧凑对齐，留出空间扩展操作。
   - 大纲与文件名文本启用单行截断（`text_ellipsis`），杜绝跨行折行破坏纵向节奏。
   - 大纲标题强化层级视觉区分：H1 采用加粗与主字色，H2 采用中等字重，H3+ 采用次级弱化文字色（`text_muted`）。
5. **默认主题暖石色阶 (Warm Stone Grayscale) 调优**：
   - 原默认浅色主题灰阶误用了冷蓝 Slate 灰（`#F0F0F4`, `#E2E2E8`，色相 240°），与暖陶土珊瑚红（`#D9532F`，色相 12°）产生明显杂色违和感。
   - 切换为暖石纸张灰阶（Warm Stone Gray）：背景 `#F5F4F0`、边框 `#E6E4DE`、正文字色 `#2C2A29`、次级字色 `#787571`、代码块背景 `#EFECE6`，使整套视觉温润一体、具有高级社论印刷质感。

## 决策 (Decision)
1. 在 `AppState` 中扩展 `open_docs: Vec<Document>` 和 `active_doc_idx: usize`，实现零成本的多标签状态管理。
2. 在 `WorkspaceView` 中集成横向标签页条（Tab Strip），支持点击切换、关闭标签与快捷键 `⌘W`。
3. 改造 `drawer.rs` 抽屉侧边栏：纯图标左对齐、Hover Tooltip、文本省略截断、H1/H2/H3+ 阶梯字重与色彩降噪。
4. 修正 `theme.rs` 中 `default_palette` 的浅色与深色灰阶，与暖陶土主题色完全契合。

## 结果 (Consequences)
- 支持多文件并发阅读与编辑，标签页切换流畅无感，内存增量微乎其微。
- 侧边栏结构精致现代，长标题不再折行破坏版面，大纲结构一目了然。
- 默认主题彻底告别发青发冷的杂色感，形成优雅温润的暖石纸张视觉基调。
